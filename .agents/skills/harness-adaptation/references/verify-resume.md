# 原会话验收

## 先拿到可对照的原会话

1. 用目标 Harness 的原生客户端在受控项目创建会话，留一条容易辨认的历史消息。记录原生 ID、真实项目路径、执行器及版本、初始模型或权限。要给用户已有对话实发消息时，先确认本次授权包含该对话的实发测试。
2. 从执行器或手机的项目列表找到它，打开历史并翻到记录的消息。分开确认列表按项目、分页正确，以及订阅与原生 ID 一致。
3. 通知执行器恢复同一个原生 ID，核对原生返回的 ID 和当前选中模型。需要接管运行中会话时，单独验证官方共享连接、已有轮次和原生停止方式。只能在释放后恢复时，分别记录占用时的提示和释放后的成功证据。
4. 选择本机实际可用的模型后发一条纯文本测试消息，例如要求只回复 `HARNESS_RESUME_OK`。尽量在本次测试的原生配置中把工具调用限制到验证所需的范围。记录唯一命令 ID。等待有正文的原生完成事件。重开原生会话或从其历史接口读回新增的用户消息和助手回复。
5. 从原生执行记录核对这条新回复的模型、provider 和会话 ID，核对结束状态。若该版本未提供实际执行模型的证据，把「保存选择」「请求使用」和「实际模型已确认」分别记录。

## 按影响范围补验收

| 场景 | 通过证据 |
| --- | --- |
| 多条会话 | 同项目两条对话分别恢复到各自 ID，各自保存模型与权限；切换后重开仍各自生效。 |
| 目录或授权变化 | 能刷新原生可用模型；保存模型暂不可用时保留可理解的名称，显示可选项并可切换。真实账号用一次请求证明鉴权可用。 |
| 权限与工具 | 在安全项目触发良性工具请求，核对原生选项、手机允许或拒绝的回执及实际效果；重复答复和已经结束的请求妥善处理。 |
| 流式与历史 | 验证至少一个增量、一个完成事件，重连或切换页面后正文、轮次和工具状态能对齐原生历史。 |
| 断线与重复投递 | 断开后按游标恢复，缺增量时以快照接回。使用原命令 ID 重投或查询，原生历史只出现一次相应的用户消息；模糊结果显示待核实。 |
| 打断或排队 | 在有关能力中选择场景，验证打断针对原生当前轮次，或下一轮只按队列顺序发送一次。 |
| 权限隔离 | 用受控测试节点和目录验证鉴权、共享目录检查、会话 ID 归属和跨项目隔离。 |

## 记录执行环境

用夹具覆盖事件顺序、超时及不支持的权限。用真实本机 CLI 或宿主核对原生协议。仅在本次授权包含发布时，确认实际安装或线上运行的提交、两端资源、原配对在线，再用同一条会话做线上读回。记录哪一环境发了测试消息，哪一环境验证了列表、历史或设置。

Dovun 例子取 0.6.15（`fcc58fe`）。先在 Mac 上用真实智谱账号对原对话发纯文本测试，原生会话存储证实回复使用 GLM-5.4。双端发布后从正式站读取同一个 ID、最新页和更早一页历史，模型列表有 4 项且原会话选择仍是 GLM-5.4。

Dovun 可复用的入口包括 `server/src/node-agent/harness-protocol.ts` 的能力和消息契约、`server/src/node-agent/harness-controller.ts` 的命令与恢复、现有会话工具栏与审批组件。相关回归位于 `server/src/harness-sessions.test.ts`、`server/src/node-agent/harness-zcode-live.test.ts` 和 `e2e/harness-sessions.spec.ts`。浏览器用例在 `webkit-chat` 项目内创建手机视口。运行前确认测试数据库和端口隔离。
