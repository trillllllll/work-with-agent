# Harness 适配

接入本机 Harness 时，沿用执行器、会话页面和中继的公共契约。让适配器调用当前安装版本的原生协议。用原会话里的新回复验证续聊。

## 先确认要接入的能力

- 记录用户要求的范围、执行端实际启动的程序路径、版本、启动方式、项目目录和账号来源。桌面应用、CLI、SDK 与内置运行组件分别核对。调查、实现、正式发布按本次授权执行。
- 以现有执行器的启动入口定位代码。先读当前二进制的 `--version`、`--help` 和对应版本官方协议或源码。再用同一启动参数和账号做有限的能力探测，留存模型 ID、权限值、回执和会话 ID 对应关系等必要证据。日志和验收记录省略凭据、完整配置及无关历史。
- 给每项能力记下原生方法或 CLI 参数、输入和回执、何时生效、账号或管理策略的限制，以及验证结果。分别查清历史读取、冷恢复、接管正在运行的会话和新建会话。可用性随着版本、当前模型和本机策略变化。界面根据已探测到的能力显示设置和操作。

## 复用边界

| 共用部分 | 适配器负责的部分 |
| --- | --- |
| 执行器配对、共享目录校验、项目选择、本机进程生命周期 | 找到实际 CLI 或宿主，识别会话归属和原生进程占用，选择受支持的附接或恢复方式 |
| 同一套按项目列表、聊天、执行过程、模型设置与审批组件 | 原生模型 ID 和名称、思考档位值、权限说明、工具结果和原生审批选项 |
| 中继投递、`commandId` 去重、执行回执、SSE 快照与增量 | 原生读历史、发送、追发或排队、打断及审批，对齐原生命令和事件状态 |
| 会话绑定、按会话保存设置、旧客户端与执行器能力协商 | 按原生会话 ID 恢复，读取有效设置，根据原生能力决定设置生效时机 |

分开管理应用的会话 ID 和 Harness 的原生 ID。绑定保留 Harness 类型、节点、经校验的项目路径和原生 ID。区分投递成功、原生已受理和模型已回复。超时后查原命令回执。重连接原游标，缺失增量时读取快照，并丢弃旧连接代次的迟到事件。

模型至少区分保存的选择、当前可用列表和实际回复采用的模型。权限分别记录文件访问范围、询问或自动审批规则、计划模式、管理策略及生效时机。共用文案用 `{{harness}}` 一类的占位符传入当前名称。权限档位的本地化名称和说明根据各自原生行为维护。直接用原生选项渲染审批，由原生回执确认结果。会话上下文、推理档位、计划模式和高级权限按已验证的能力展示。

## 查对应 Harness

- Codex 使用 App Server 的 schema、模型列表、配置要求及 thread 接口。[Codex 接入参考](references/codex.md)
- Claude Code 使用实际 CLI 的流式接口或 Agent SDK，核对生效权限和会话 UUID。[Claude Code 接入参考](references/claude-code.md)
- ZCode 分别核对本机 V4 会话协议、当前模型目录和负责账号鉴权的宿主。[ZCode 接入参考](references/zcode.md)
- 接入其他 Harness 时，先按以上方法验证对应的原生能力，再决定哪些字段可以映射到共用契约。使用该 Harness 当前版本支持的启动方式、数据源和权限值。

## 验证续聊

先在受控项目用原生客户端创建有可识别历史的会话。通过执行器找到并恢复同一个 ID、翻到历史锚点、发送一条纯文本验证消息。确认原生回复完成，重开原会话后两端都能读到该回复，并尽可能从原生元数据核对实际模型。用授权范围内的真实账号验证可用性。多会话、权限、断线与去重按受影响的场景验收。[原会话验收流程](references/verify-resume.md)
