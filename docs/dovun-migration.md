# Dovun 迁移与交付手册

本文记录独立 0.3.0 过渡版的行为。当前 0.4.0 分支另见 [新身份迁移](dovun-04-handoff.md)。没有执行本机安装、实际数据迁移、仓库改名或服务器部署。

## 0.3.0 的实际行为

- 工程包、服务进程、MCP 默认名称使用 Dovun；桌面包名 Dovun，系统标识仍为 `app.workwithagent.desktop`。
- `DOVUN_*` 优先，旧 `WWA_*` 回退一版；同一设置不同时提示键名，不输出值。容器默认值在显式配置之后生效。原 `.env` 不需要立即改写。
- 新安装默认 `dovun/dovun.db`。桌面默认目录旁发现旧 `work-with-agent` 时，在本机 API 和执行端启动前运行离线迁移。显式自定义数据路径继续使用原路径，不擅自搬走；已有数据库文件名仍可读，两个名称同时存在则停止。
- 容器既有卷保留 `agent-studio.db`，新卷用 `dovun.db`；不为了改名新建空工作台。自动快照仍默认 `/data/snapshots`，显式空值可关闭。
- 浏览器本地/会话偏好逐键迁移一次；原值留作恢复来源，清除新值后不再次复活。任务草稿从旧 IndexedDB 复制，保留 origin、服务、用户、任务和分支范围；冲突保留为恢复分支，不覆盖较新的编辑。迁移失败时显示恢复错误，阻止打开空工作台。
- 新旧桌面事件、通信路径、语言头与会话 cookie 在本版兼容。已有 MCP 连接更新原条目；默认 macOS 旧绝对路径启动器在迁移成功后转发新资源，远程模式也执行更新。Windows 指向旧应用资源的宿主配置需在最终安装时更新原条目。

## 离线目录迁移

先退出旧桌面应用、停止对应 API、执行端和 runner。容器迁移需先停止容器；不能只看桌面 47316 端口。来源、目标分别保存，先确认磁盘能容纳原目录、完整备份和完整新目录。

```bash
# Node >= 22；先按项目要求更新并提交应用功能知识，再构建。
node server/dist/desktop-migrate.js '/absolute/old-folder' '/absolute/dovun' 47316
```

第三个参数是待停止服务的宿主端口；开发服务用 3016，原部署用 12716。迁移工具不停止服务。任一占用、执行端未停、启动租约活跃时拒绝执行。

工具先逐文件 SHA256 记录，再复制完整来源到同级 `.backup-<时间>-<随机值>`；校验备份后建立临时新目录，重命名数据库及 WAL/SHM/journal，核对全部资料、执行记录和配置，再检查复制库的完整性及任务表。最后再次核对来源与服务状态，原子切换目标目录。原数据库不打开、不写入，保留原目录和备份；失败清理临时目录并停止切换。

`.dovun-migration.json` 是核对凭证，含来源、备份位置和文件摘要，不含正文或令牌。重复执行允许新目录正常产生后续数据，但旧来源若有新增内容则停止，避免丢掉旧版继续写入的工作。受管理的旧 MCP 转发脚本是唯一允许变化的来源文件。

新旧目录都有数据而没有匹配记录时，不自动选择、合并或覆盖。分别备份后由使用者选择来源，另选空目标执行；不要删除某一边来绕过冲突。符号链接和特殊文件拒绝迁移，需先在独立离线副本中实体化。

开发数据导入使用同一规则：`node scripts/import-desktop-data.mjs --source-dir <来源> --data-dir <空目标>`，完整复制来源目录。自定义的外部资料/runner 路径需先单独盘点备份，不会自动猜测路径。

## 0.4.0 的发布门槛

必须单独验证 `app.dovun.desktop` 的原生浏览器状态恢复，覆盖经过/跳过 0.3.0 两条路径，再移除旧环境变量回退、MCP 启动别名和旧通信入口。新身份第一次打开前恢复偏好、会话恢复信息和有作用域的草稿，不能静默进入空状态。历史备份与正文中的资料链接解析长期保留。

此门槛尚未通过，不把 0.3.0 的兼容保留当作 0.4.0 已完成。

## 最终切换检查

仓库地址、域名、Compose 服务/容器名、`/opt/work-with-agent` 和真实数据目录仍保持可用。后续切换另行执行：停止并确认服务 → 记录真实数据大小/摘要与 `.env` 存在 → 备份 → 覆盖原安装/原部署 → 核对版本、资源哈希、健康、数据 → 恢复访问。不得新增第二个宿主 MCP 条目或第二个同宿主连接。

macOS、Windows 的代码路径都有覆盖；本机只能产出和验证 macOS Apple Silicon 包。Windows 原生安装和 WebView2 升级验收需在 Windows 环境执行。源码、候选包、实际安装、公网验收分别记录，不能相互代替。
