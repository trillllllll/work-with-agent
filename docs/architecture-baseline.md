# Agent 工作室：第一版架构基线

## 1. 架构分层

```text
表现层
├── 全局聊天
├── 任务看板
└── 主题与成果视图

应用层
├── 对话 Agent
├── 任务管理
├── 主题管理
└── Agent 闸门

领域层
├── 主题
├── 任务
├── 任务成果
└── 协作记录

基础设施层
├── 数据存储
├── 模型适配器
├── 上下文压缩
├── 日志
└── 执行环境（可选）

外部系统
└── OpenAI 兼容模型服务
```

分层职责：

- **表现层**：接收用户输入，展示聊天、任务、主题和成果。
- **应用层**：编排完整用例，协调 Agent、任务管理、主题管理和审核流程。
- **领域层**：表达工作室的核心业务概念，不依赖具体技术实现。
- **基础设施层**：提供数据、模型、上下文、日志和可选执行环境等技术能力。
- **外部系统**：应用无法控制、通过接口连接的模型服务。

## 2. 核心约束

1. 任务是核心对象，任务必须归属于主题。
2. 主题可以从“探索主题”逐步收敛为明确目标和成果。
3. Agent 是协作者，不是状态的最终拥有者。
4. Agent 只能通过 Tool 访问数据库内容。
5. 读取操作可以直接执行。
6. 所有会产生副作用的 Tool 调用都必须经过 Agent 闸门。
7. 审核粒度是一次 Tool 调用。
8. 每次 Tool 调用都保存审核和执行记录。
9. 任务、主题、计划状态只有业务模块维护。
10. 全局聊天只默认携带最近任务和当前页面上下文。
11. 更早或更广的数据通过 Tool 按需读取。
12. 对话历史需要上下文压缩机制。
13. 主题总结必须经过用户确认。
14. 数据变更支持撤销，外部副作用暂时只记录。

## 3. 核心运行链路

```text
用户
  ↓
全局聊天 / 看板
  ↓
对话 Agent
  ↓
读取：直接调用 Tool
修改：提交 Agent 闸门
  ↓
用户审核
  ↓
任务管理 / 主题管理
  ↓
领域状态更新
  ↓
数据存储与协作记录
```

## 4. 关键业务理解

任务不只是预先规划好的工作项。每个任务必须有一个主题；当方向尚不明确时，可以先归入“探索主题”。随着任务持续积累，主题逐步形成清晰的目标、阶段结论和最终成果。

全局聊天是讨论所有任务的入口，同时携带当前页面和当前对象的上下文。聊天默认只注入最近任务和当前页面上下文；需要更早或更广的数据时，由 Agent 通过 Tool 按需读取，并使用上下文压缩机制控制对话长度。

Agent 可以读取信息、分析和提出操作，但不能绕过业务模块直接改变状态。任何会改变数据、文件或外部系统状态的 Tool 调用，都必须经过 Agent 闸门并由用户审核。

## 5. 当前范围

这是开发实施用的第一版架构基线。它确定模块职责、依赖方向和安全边界，不提前锁定执行环境（沙盒）的具体技术方案。
