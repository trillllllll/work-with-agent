# Internationalization (zh-CN / en)

Simplified Chinese is the default language everywhere; English is the second language.

## Client

- `client/src/i18n/`: i18next, with resources bundled per namespace in `locales/<lang>/*.json`.
- Language order: the choice made in Settings → Language (saved in `localStorage` under `wwa.language`), then the browser language, then zh-CN.
- Every API call sends the chosen language in the `X-WWA-Language` header (`authHeaders()` in `client/src/lib/api.ts`).

## Server

- `server/src/i18n/index.ts`: picks a locale per request. It reads `X-WWA-Language` first, then `Accept-Language`, then falls back to zh-CN. The locale is kept in AsyncLocalStorage for the life of the request.
- Messages stay in Chinese in the source. `server/src/i18n/locales/en.ts` maps each Chinese source message to English. Template literals become positional placeholders (`` `a${x}b` `` → `"a{0}b"`).
- Translation only happens at the HTTP boundary:
  - JSON responses: message fields (`error`, `message`, `reason`, `warnings`, …) are translated.
  - Chat SSE events are translated the same way.
  - zod validation messages are translated.
  - Labels the server puts into data go through `localize()`, e.g. task activity actors and knowledge graph branches.

  Stored data, model-facing tool results and the server tests keep the Chinese source text.
- MCP over HTTP forwards the caller's `Accept-Language` to the API. MCP over stdio can set `WWA_LANGUAGE=en`. Otherwise responses are zh-CN.
- `scripts/server-messages.mjs` collects the user-visible messages. These are:
  - the message argument of `DomainError` / `new Error` / `fail` / `notFound` / …;
  - zod messages;
  - `error` / `message` / `errorMessage` properties;
  - `localize()` labels.

  `npm run i18n:check` fails when any of them has no English entry, when an entry is stale, when placeholders differ, or when English still contains Chinese.
- To add a server message, write it in Chinese as usual, then add the English entry to `locales/en.ts`. A line comment with `i18n-ignore` excludes a string on purpose.

## Assistant replies

The model prompts are deliberately kept in Chinese and were not rewritten. When the chat request's language is English, `startChat` stores `language: 'en'` in the run context. `assembleRunMessages` then adds a single instruction (`replyLanguageInstruction`) telling the assistant to reply in English. With zh-CN nothing changes.

## Desktop

`desktop/splash/index.html` follows `navigator.language`. The launcher's Rust error messages (`desktop/src-tauri/src/lib.rs`) follow the system language through `src/i18n.rs`:
- Windows: `GetUserDefaultUILanguage`.
- macOS: `AppleLanguages`.
- Otherwise: `LC_ALL` / `LC_MESSAGES` / `LANG`.

The result is English for `en*` and Chinese otherwise.

## Kept in Chinese on purpose

| What | Where | Why |
| --- | --- | --- |
| Model prompts, tool descriptions, app knowledge, memory-extraction prompts | `server/src/agent/*`, `server/src/application/auto-memory*.ts`, `client/src/lib/organization-prompt.ts` | Model-facing. Tests and the server match this wording. The reply language is handled by the instruction above. |
| `userRejectedError` (`用户拒绝，数据未修改`) | `client/src/chat.ts`, `server/src/agent.ts` | Protocol text. The client recognises rejected tool results by exact match. |
| `replyIncompleteMarker` (`后续回答未完成`) | `client/src/chat.ts`, `server/src/agent/runs.ts` | The client matches it inside SSE error messages. |
| Handoff acceptance heading (`验收标准与产物：`) | `client/src/components/workspace/HandoffPanel.tsx` | Becomes part of the instruction sent to the local AI and stored with the handoff. |
| Memory reason strings (`用户将该记忆设为历史`, `用户修订`, `人工记录`, `来自全局聊天`, `退役不再进入上下文`, `撤销本体更名`) | `KnowledgePage.tsx`, `server/src/application/agent-memory.ts`, `knowledge-graph.ts` | Stored with memory versions as audit data and matched by tests. |
| `当前简报` heading | `KnowledgePage.tsx` | Matches the heading of the server-generated brief. |
| Stored and generated content: change-history text, artifact names (`完整代码变更.patch`), AI summaries, reviews, briefs and extracted memories | database | Data, not UI. AI output follows the prompt language. |
| Server logs and CLI-only scripts (migrations, rehearsals, `console.*`) | `server/src` | Not shown in the app. |
