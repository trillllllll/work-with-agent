# 滴答清单「任务动态」调研

> 调研日期：2026-09-29
> 范围：滴答清单及其国际版 TickTick 的单条任务改动记录。对照了现行帮助中心、旧版用户手册、2022–2023 年公开教程，以及公开任务接口文档。没有登录账号，也没有打开当前客户端界面。
> 证据等级：现行帮助中心是主来源。旧手册和教程只用来补「记了哪些字段」，文中单独标出，不把它们写成今天的产品事实。

滴答清单（Dida365）和国际版 TickTick 的帮助中心是同一套说明的中英两版。下面以滴答清单的中文说法为主，「Task Activities」是英文名。

## 结论

「任务动态」挂在单条任务上。它是一条从创建到完成的改动时间线，用来回看被改掉的正文，以及在共享清单里看出是谁改的。它不是评论，也不是「已完成」清单或摘要。

现行帮助中心写明了入口和用途，没有逐条列出字段，也没有在这一节写会员限制。能对上的字段来自旧手册和教程：创建、标题或正文、日期、附件、指派人、完成，以及后来教程里看到的所属清单迁移。优先级、标签、提醒、进度、子任务、置顶、放弃，公开材料没有逐项证实。

完整动态是否仍是高级会员功能，现行帮助中心没有写。旧手册和 2022–2023 年的用户回复说是会员功能。

## 它解决什么

现行帮助中心把用途说成两件具体的事：辛苦编辑的文字被删了，要找回历史；共享协作时，要知道任务被谁改过。英文版用的是同一对例子：误删正文，以及协作中不清楚修改者。

定义也是同一句。中文常见问题写：「任务动态是指任务从创建之初到被完成时的所有改动记录。」英文 FAQ 写：from its creation to completion。

来源：[任务详情与编辑](https://help.dida365.com/articles/6950661731483910144)、[常见问题 · 如何查看任务动态](https://help.dida365.com/articles/6950670128287580160)、[Task Details](https://help.ticktick.com/articles/7055782408586526720)、[FAQ · How to view Task Activities](https://help.ticktick.com/articles/7055792921664028672)。

## 入口

现行中文帮助的路径是：打开任务，在详情页右上角点「···」，再进「更多」，选「任务动态」。任务详情页把同一步写成右上角「...」→「更多」→「任务动态」。英文帮助是详情页右上角 “...” → Task Activities；FAQ 只写到点详情页的 “...” 图标。

旧版 Android / iOS 用户手册还描述过两层：

| 层 | 当时的入口 | 当时能看到的内容 |
|---|---|---|
| 动态概要 | 任务详情里向上轻拉，出现在底部 | 创建日期、完成日期。高级会员还能看到是谁创建、谁完成 |
| 完整动态 | 详情右上角菜单 →「动态」。手册标明这是高级功能 | 创建日期、标题/内容改动、日期改动、附件上传与删除、指派人改动、完成日期 |

现行帮助中心只保留菜单里的完整动态，没有再写底部概要。概要是否还在，本次没有登录复核。

来源：上面的现行帮助页面；旧手册 [Android · 管理任务](https://xwzappest.gitbooks.io/guide-dd/content/android_app/3_manage_tasks.html)、[iOS · 管理任务](https://xwzappest.gitbooks.io/guide-dd/content/ios_app/3_manage_tasks.html)。

## 记了什么

下面按来源分开，不合成一份「当前完整字段表」。

| 来源 | 时间 | 写明或演示过的记录 |
|---|---|---|
| 旧版 Android / iOS 手册 | 手册页面未标版本；内容早于现行帮助中心的菜单结构 | 创建日期；标题/内容；日期；附件上传与删除；指派人；完成日期 |
| 少数派教程 | 2023-07 | 内容变化、到期时间、完成时间。「所有变动」是作者的概括，后面用「等」带过 |
| TickTick 课程实录 | 2022-03 | 演示里出现了样式改动、新增描述、到期日和时间、添加附件。讲述者称误删的描述可以从这里找回 |
| 完成任务回顾视频 | 2023-08 | 讲述者列举时间关联、所属清单迁移、完成状态，并说明未完成的任务也能打开这条记录 |

2023 年 8 月的视频把清单迁移算进任务动态。旧手册的字段表里没有这一项，所以「移动清单会留下一条动态」只算教程观察，不是现行帮助中心的原文。

公开材料没有逐项证实这些改动会进任务动态：优先级、标签、提醒、重复、进度百分比、检查事项、子任务、置顶、放弃、评论本身。2022 年 Reddit 上有人希望看到优先级、清单和推迟记录，回复只说入口在 Task Activities，没有列出实际字段。

来源：[少数派 · 01 收集与整理](https://sspai.com/post/79148)、[The Complete Guide to TickTick · The Elements of a Task](https://www.youtube.com/watch?v=sCpMZRc2MkM)、[TickTick: How to Review Completed Tasks](https://www.youtube.com/watch?v=mL0IBy7HknM)、[Reddit · Task History?](https://www.reddit.com/r/ticktick/comments/s8wadc/task_history/)。

## 和评论、清单动态的边界

评论是人写的备注，动态是系统记下的改动。现行帮助写：共享清单里用评论做协作；自己的清单里也可以把评论当备注。入口和动态分开。英文 FAQ 中，移动端是详情「...」→ More → Comment，桌面端是详情右下角的评论图标。

评论长度在 2018-04-18 的更新日志里写成最多 1024 字。2022 年课程和 2023 年少数派教程仍用这个上限。本次打开的现行「任务详情」页没有重申字数。2024-08-31 的更新给评论加了图片附件。

清单还有另一条时间线，英文桌面端叫 List Activities。2023-02 的桌面教程把它和任务动态分开：

- 清单动态记录的是清单上的事：创建清单、任务移入、在清单内创建任务、在清单内完成任务、任务移出、删除任务。演示里，操作者名字和时间（“just now”）跟在动作后面。
- 它不记录任务自己的字段，例如改到期日、加评论。这些仍要进该任务的任务动态。
- 任务进垃圾桶后再永久删除，清单动态里原来的任务名会变成 unknown。

现行中文帮助中心没有搜到对应的「清单动态」文章。这条时间线是否还在 2026 年的客户端里，本次没有复核。该视频下有一条评论说这是会员功能，帮助中心没有佐证。

来源：[任务详情与编辑 · 评论](https://help.dida365.com/articles/6950661731483910144)、[FAQ · How to comment on tasks](https://help.ticktick.com/articles/7055792921664028672)、[Changelog · 2018-04-18](https://ticktick.com/public/changelog/en.html)、[Updates in 2024 · Enhanced Task Comments](https://help.ticktick.com/external/articles/7301088783166865408)、[How to view List Activities](https://www.youtube.com/watch?v=xd9G_9uDDks)。

## 旁边用到时间，但不是这条动态

这几项消费的是创建时间、修改时间或延期次数，不是任务详情里的改动日志：

- **推荐任务**在「今天」里按创建时间、到期日改过几次、是否过期来分组。其中「延期任务」按改期次数从高到低排，并分成超过 5 次、3 次、2 次。帮助中心没有说这些次数来自任务动态页面。
- **分组和排序**在 2026-07-10 增加了按创建时间分组，以及按创建时间、修改时间排序，可选最新在前或最早在前。这是列表顺序，不是一条可回看的历史。
- **已完成**智能清单和摘要按完成结果回顾任务，可以按时间、清单、优先级过滤。它们不展示标题、正文、附件的前后差异。

2023 年的产品拆解还提到笔记也有「动态」，并称要高级会员。那篇文章没有给出帮助中心链接，本次也没有在现行帮助里复核笔记动态。

来源：[Suggested Tasks](https://help.ticktick.com/articles/7401564165023727616)、[Manage Tasks with Group & Sort](https://help.ticktick.com/articles/7056594711640801280)、[Changelog · 2026-07-10](https://ticktick.com/public/changelog/en.html)、[人人都是产品经理 · 拆解滴答清单](https://www.woshipm.com/pd/5859356.html)。

## 会员

三处旧材料把更完整的动态放在高级会员后面，现行帮助中心的任务动态段落没有写付费墙：

| 来源 | 说法 |
|---|---|
| 旧版用户手册 | 底部概要里，创建人和完成人仅高级会员可见；菜单里的完整动态标为高级功能 |
| Reddit，2022-01 | 一条回复写 Task Activities 仅 Premium |
| 清单动态教程评论，2023-02 | 一条评论写 List Activities 是会员功能 |

因此只能说：至少在 2022–2023 年的客户端里，完整动态被当作会员功能。2026 年 9 月的帮助中心没有重申，也没有宣布改为免费。

## 接口里看不到这条时间线

公开的 Open API v1 覆盖任务的读取、创建、更新、完成、删除，以及清单列表。本次看到的接口说明里没有 activity 或 history 资源。

非官方客户端走的是网页同一套内部接口。`@ticktick/ticktick-cli`（页面标注发布于 2026-09-22）能列出、添加、删除评论，路径是 `/project/{projectId}/task/{taskId}/comments`。同一份命令表里没有任务动态。任务对象本身带 `createdTime`、`modifiedTime`、`creator`、`completedTime`，这是几个时间点，不是改动列表。

来源：[TickTick Open API 镜像](https://gist.githubusercontent.com/szelemeh/79f131f908ad9b548e955fa308580cad/raw/ticktick_open_api.md)、[@ticktick/ticktick-cli](https://www.npmjs.com/package/@ticktick/ticktick-cli)。

## 和本仓库的差距

work-with-agent 现在没有任务详情里的逐字段动态。相近的记录是另外两处：

- 任务的清单归属历史，`GET /api/tasks/:id/topic-history`。原因是 `created`、`assigned`、`unassigned`、`topic_archived`、`undo`、`migration`，每条有时间和来源清单、目标清单。见 `client/src/lib/api.ts` 的 `TaskTopicHistory`。
- 工作区「变更历史」按清单、标签、任务、受控执行筛选，用来查看并撤销仍可逆的操作。它是命令审计，不是某条任务的字段时间线。

项目记忆另有修订史。那是记忆正文的版本，不记录任务标题、日期或附件的改动。
