# 规划页时间轴：父子相邻与手动换列实施计划

日期：2026-10-26  
状态：已实现  
范围：规划页日视图、周视图的时间轴；不改动任务列表排序和月视图排期语义。

## 1. 背景与现状

当前时间轴先按开始时间、持续时长、任务 ID 排序，再在重叠任务组中分配列：

- 未完成任务优先占用最左侧空列。
- 已完成任务优先占用最右侧空列。
- `parentId` 和 `sortOrder` 不参与时间轴布局。
- 拖动只修改日期、开始时间、结束时间或取消安排，没有“左右换列”落点。
- 拖动中的固定展示只用于避免任务被折叠进“+N”，不是持久化排序。

因此，完成任务会导致卡片换列，父子任务也可能被拆开。

## 2. 产品判断

滴答清单官方说明能确认：列表排序不会破坏父子层级；子任务在日历中仍是可独立设置时间、独立拖动的完整任务。官方资料没有明确说明同时间段任务的左右列规则，也没有确认“已完成靠右”或“时间轴手动换列”。本方案借鉴其“列表表达层级、日历表达时间”的边界，不把未证实的行为描述成照搬。

核心原则：

> 时间决定上下，父子关系决定默认左右，用户手动顺序优先；完成状态只影响样式，不影响位置。

布局优先级：

1. 当前重叠组的手动顺序。
2. 可见父子任务相邻，主任务在子任务之前。
3. 任务组按最早开始时间排列；同级子任务参考现有 `sortOrder`。
4. 持续时长和任务 ID 仅作稳定兜底，不覆盖父子关系。
5. `status` 不参与列分配。

## 3. 交互定义

### 3.1 默认布局

- 仅在同一个重叠任务组内保持父子相邻，不跨不相关的时间段强行分组。
- 主任务与可见子任务形成连续序列；多级任务按先父后子展开，同级按 `sortOrder`、开始时间、ID 排序。
- 父任务不可见时，可见兄弟仍尽量相邻，并将该可见家族视为一个排序单元。
- 无父子关系的任务保持按时间布局；不额外增加列，列数仍由最大并发数决定。
- 完成、恢复完成、刷新、切换显示已完成，不应仅因状态变化而重排。
- 已完成样式继续使用透明度和删除线，不改变卡片尺寸。

### 3.2 手动换列

- 在时间轴内将任务水平拖向同组另一张卡片，并落在其左半边或右半边时，执行换列／插入排序。
- 换列只修改当前重叠组的展示顺序，不修改 `dueDate`、`scheduledStart`、`scheduledEnd`、时长或任务层级。
- 拖到空白时间格、全天区域、另一日期或待安排区，继续走现有排期逻辑。
- 跨日期拖动优先解释为修改日期，不触发换列。
- 拖动过程中给出插入位置预览；松手后保存，取消拖动不保存。
- 被拖任务继续保持可见，不与现有“避免折叠进 +N”的能力冲突。
- 触屏沿用长按激活；只有明确水平意图且落在同组卡片上才进入换列，避免与时间轴滚动竞争。

### 3.3 顺序保存边界

- 不复用任务清单的 `sortOrder`，避免时间轴换列意外改变清单顺序。
- 第一阶段使用规划页独立的本地展示偏好，不改任务表、同步协议或服务端 API；换机／多端同步不在本次范围。
- 偏好按“日期 + 重叠组身份”保存。组身份至少包含日期、组起始时间及组内任务 ID，防止同一天不同时间段互相污染。
- 刷新、重开应用、完成状态变化后，只要组身份未变，就恢复手动顺序。
- 新增／移除任务、组拆分或合并、排期导致组身份变化时，回到默认布局；不猜测旧顺序应如何迁移。
- 提供读取、写入、清理损坏数据和容量裁剪的独立工具；存储不可用时退化为本次页面会话内的顺序，不阻塞排期。

## 4. 技术实施

### 4.1 纯布局函数

主要文件：`client/src/lib/plan-layout.ts`。

- 保留现有按时间建立重叠组的算法，避免家族排序破坏分组正确性。
- 在组内新增默认排序层：构建可见任务家族，按根任务时间对各家族排序，家族内先父后子。
- `assignLanes` 删除完成状态选列分支，统一使用最左侧可用列。
- 为 `layoutLanes` 增加可选的组内顺序输入；手动顺序只影响对应组。
- 保持 30 分钟最小占位、最大并发列数、`+N` 折叠和 `pinnedTaskId` 可见性规则。
- 输出仍使用现有 `LanePlacement`，尽量不重写卡片渲染和样式。

### 4.2 本地展示偏好

建议新增：`client/src/lib/plan-lane-order.ts`。

- 定义版本化存储结构、重叠组身份计算、顺序校验和读写接口。
- 过滤不存在、重复或非法的任务 ID。
- 限制保存的日期／组数量，优先淘汰最久未使用记录。
- 存储键使用独立命名，例如 `dovun.plan.laneOrder.v1`；不得覆盖现有规划页偏好。

### 4.3 拖动与渲染接入

主要文件：`client/src/components/plan/PlanPage.tsx`。

- 为时间卡片增加换列所需的放置目标与任务组信息。
- 在碰撞检测中区分“同组卡片换列”和“时间格排期”，跨日期目标始终优先排期。
- 在拖动状态中记录换列意图、目标任务和插入方向；换列预览不写入 `SchedulePatch`。
- `onDragEnd` 分支处理：排期继续调用 `save`，换列只保存展示偏好并刷新布局。
- `onDragCancel` 完整清理两种拖动状态。
- 保留现有跨天片段偏移、30 分钟吸附、调整时长、触摸点击防误触和自动滚动行为。
- 如需提示文案，补齐中英文资源；优先用视觉插入指示，不增加常驻说明。

## 5. 测试计划

### 5.1 布局单元测试

更新 `client/src/lib/plan-layout.test.ts`，覆盖：

- 主任务和子任务同时重叠时默认相邻，主任务在前。
- 多级任务、多个兄弟、多个家族混合时顺序稳定。
- 父任务不可见、子任务跨天、仅部分家族成员落入当前组时不报错。
- 已完成任务不固定靠右；完成状态变化前后列位置不变。
- 同开始时间下，父子关系优先于持续时长和 ID 兜底。
- 手动顺序覆盖当前组默认顺序，但不影响其他组。
- 不新增无意义的列；同列任务不重叠，最大并发数和宽度计算保持正确。
- 超出列上限时 `+N` 数量正确，被拖任务仍保持可见。
- 保留现有随机布局不变量测试。

### 5.2 偏好与拖动测试

新增偏好单元测试，并补充规划页交互／E2E：

- 存储读取、损坏 JSON 回退、重复 ID 清理、容量裁剪。
- 同组左插、右插、交换及取消拖动。
- 换列保存后刷新仍有效，任务时间字段完全不变。
- 完成任务后不换列，清单 `sortOrder` 不被修改。
- 拖到时间格仍修改时间，跨日期拖动不被识别成换列。
- 组新增／移除／拆分后恢复默认顺序。
- 鼠标与触屏手势不冲突，拖动后的点击防误触仍有效。
- 窄屏、日视图、周视图和 `+N` 场景完成冒烟。

## 6. 实施顺序

1. 先改纯布局：移除完成状态选列，加入父子相邻，不接入拖动。
2. 补齐布局测试，确认并发、折叠和跨天行为没有回归。
3. 增加独立的本地顺序偏好及测试。
4. 接入同组换列、插入预览和拖动状态清理。
5. 完成鼠标、触屏及排期回归，再处理窄屏细节。
6. 运行相关单元测试、`npm test`、构建及必要的 E2E；若后续要求打包发版，先按仓库要求更新并提交 `appKnowledge`。

## 7. 验收标准

- 可见父子任务在同一重叠组内默认连续，完成状态不再决定左右。
- 用户可在同一时间段内通过水平拖动调整左右顺序，且不会改变任何排期字段。
- 刷新和重开应用后，同一重叠组保留手动顺序。
- 清单排序、任务层级、月视图和现有时间拖动行为不受影响。
- 重叠、跨天、窄屏和 `+N` 场景无重叠错位或任务丢失。

## 8. 非目标

- 不让子任务跟随主任务自动改期。
- 不把父子关系改成依赖关系，也不根据完成状态自动重排。
- 不修改清单 `sortOrder`、数据库、同步协议或多端顺序同步。
- 不在本次增加撤销历史、服务端偏好或跨设备一致性机制。
