## 预算攻击样本与独立复核

1. **Office ZIP 声明可伪造。** 65 MiB XML 压缩后仅 66,479 B。诚实 central-directory 长度触发 `READER_BUDGET_EXCEEDED`；将同一压缩数据的声明改成 1 B 后，原 `assertOfficeArchiveBudget` 接受 `{count:2,inflated:1}`。JSZip 在真实解压后才以大小不符拒绝，本次耗时 55.48 ms，末尾仍有约 67 MiB arrayBuffers。预检 ZIP 声明本身不能充当真实解压上限。该 P1 已即时交主代理修复；应以总真实解压字节限制的流式验证先于 Office 解析器，不能只改声明门槛。
2. **XLSX 合并区可放大为大量对象。** ExcelJS 4.4.0 的 `worksheet._parseMergeCells` 调用 `_mergeCellsInternal`，对每个合并区域的每个坐标创建 Cell。很短的 `<mergeCell ref="A1:XFD1048576"/>` 可表达超过 170 亿个坐标，ZIP 字节预算及界面 100 × 30 窗口均不限制此解析行为。未运行此极端样本；源码证据已报告 P1。解析前须检查范围、合并面积和总单元格预算，超限走下载；不能把问题交给主线程解析后再发现。
3. **输入与图片路径的原始发现已修复并补测。** 首次复核时 StableBlockIds 对每次 docChanged 扫描全篇，schema 检查在 React render 执行；图片 node view 创建立即抓取原图。现已加入编辑快路径、检查缓存及视口观察；浏览器证实8张视口外图片打开时原图请求为0，滚动后8次。大正文输入仍未达50ms预算，已实施500块/256KiB编辑门槛，详见末尾实测。
4. **阅读器降级必须可见。** PDF 搜索前 500 页有提示；XLSX 合并记录只取前 10,000 条以及 PDF outline 限制应明确告知用户，不用不完整结果冒充完整读取。

## 本代理负责范围的剩余边界

- Session 已覆盖 IME 中本地落盘、禁止发版、上传完成延迟替换、最终文字与真实引用合并。真实手机输入法与软键盘未测；浏览器合成 composition 事件不能代替真机验收。
- 两个视图使用不同 `viewKey`，共用正文会话但保留各自光标/滚动缓存。外部更新现以ProseMirror公共前后边界求最小替换区间，由transaction映射各自选区，避免恢复旧绝对坐标导致前方插入/删除后漂移。3项真实PM状态测试覆盖前方块增删、文本选区两端、资源节点选区、重复文本边界及无变化；双视图浏览器用例已在Chromium和WebKit通过，见末尾收口记录。
- Session 撤销目前有 16 MiB、40 组、750 ms 组间隔内存预算；切标签/分屏仍在同会话内可撤销，刷新后仅草稿恢复，撤销栈未持久化。实现计划要求会话拥有撤销历史，未明确刷新后历史期限，需如实记录当前边界。

- 富文档/Markdown 导出保留 schema、确切版本依赖、字节与校验和；Markdown 别名映射可重新分配新 ID，源正文 CRLF不改。128 MiB/100资源上限明确报错。未知 schema 可保留导出，但当前重新导入会明确拒绝。设备未提交草稿已有独立“导出本机恢复包”入口，导出内存正文、请求状态及能读取的本地上传bytes，不发网络、不推进保存。缺失本地bytes时仍导出正文并明确提示不完整；浏览器已验证完整样本ZIP。它与服务器资源导出分别处理，不自动导入或重放请求。

## 发现后的修复与针对复验（01:40）

主代理补充实际 inflate 流计数，超过64 MiB时停止；预检不把伪造的central-directory长度当作事实。本代理在同一条流上增加 Saxes 5.0.1 SAX 校验，不保留整份XML/DOM；所有 `.xml`/`.rels` 拒绝DTD和自定义实体。使用严格UTF-8解码，无法解析的文件进入明确失败/下载流程，不修改源字节。

XLSX在ExcelJS前执行以下结构预算：行地址≤1,048,576，列地址≤16,384，定义单元格累计≤200,000，全部合并区累计面积≤200,000，单个合并区≤10,000，工作表≤100。坐标上界来自XLSX地址范围；对象数量门槛是保守产品预算，普通60,000 cell样本可通过，但尚不声称200,000 cell在手机上流畅。达到任何限制返回`READER_BUDGET_EXCEEDED`，保留原件下载，不裁剪后假装完整读取。

`archive-budget.test.ts` 6项通过，覆盖伪造size、实际inflate终止、边界地址、巨大merge、总cells/总merge/worksheet数量、DTD/自定义entity。client TypeScript检查通过。最小巨大merge包只有387 B，预检9.10 ms拒绝，未调用ExcelJS，也未分配其170亿坐标。

## 250 ms编辑缓冲与离开保护（01:54）

100 MiB上传场景发现编辑器250 ms批量序列化之前，Session尚不知道最近输入，从而漏过刷新前的本机保存检查。现保留250 ms批量转换，但首次待序列化输入立即将对应视图标为`local-pending`；Session登记每个视图的同步flush回调，切标签、关标签、切阅读或对照布局之前先把最新编辑器内容交给Session，再等待IndexedDB完成。

`beforeunload`先同步flush，再根据真实本机持久化状态阻止离开；`pagehide`/页面隐藏做尽力落盘。仅云端离线但本机已持久化的草稿不触发无谓提示。IME仍允许本机捕获、禁止发版；身份过期时只把已输入缓冲保存到原scope，不恢复网络发送。远端刷新与本地恢复包导出也先捕获编辑缓冲。

新增Session与runtime针对测试覆盖同步flush无需推进250 ms、序列化失败不冒充已保存、远端版本到达先捕获本地输入、IME只写本机、scope过期留原稿，以及真实cancelable unload事件在IDB完成前阻止、完成后允许。Session27项、runtime1项通过，client TypeScript通过。真实浏览器刷新/切换由主代理复验；用户强制确认离开、进程被杀或设备断电不可能通过异步IDB取得绝对保证，验收应先取消离开提示、等待本机保存完成再刷新，不能自动接受提示后假定数据已保存。

### 浏览器闭环与失败编辑器恢复（02:15）

独立 `/tmp/dovun-document-buffer-e2e` 库和3048/5198端口的 Chromium 100 MiB用例通过：附件初始化前bytes已存本机；同一JS任务输入后立即`beforeunload`被阻止，未加sleep；等UI确认本机durable后刷新，新增正文和占位均恢复；继续上传并保存到云端，实际原件HEAD为104,857,600 B。日志`/tmp/dovun-document-buffer-e2e.log`。此前发现刷新后新建本地文档不主动恢复上传，已修registry恢复后的reconnect；拒绝/冲突状态仍不自动重放。

最终复核又补充两个状态边界：本机flush首次捕获失败raw后，正文pump会重新检查发布许可，保持错误恢复态且不再发出旧有效正文的新请求；跨格式冲突选择远端时采用其format/schema/readOnly及scope metadata，并清除不兼容格式的undo/redo历史。已经发出的有效请求可以返回回执，但不清除raw恢复记录，也不会把该状态显示为saved。
