# 文档工作区：实现契约与使用边界

实现基线为 `d3def90a43081beb68de03917861a60396510012`；本文件描述开发分支源码。安装客户端和线上版本未随本次实现更新。

## 格式与编辑适配

| 内容 | 权威内容 | 编辑能力 | 保留策略 |
| --- | --- | --- | --- |
| 富文档 | `richdoc-v1` 产品 JSON | 标题、列表、任务列表、表格、代码语言、图片属性、固定版本附件 | 编辑器 JSON 显式编解码；未知 schema、节点或属性只读，不丢弃后保存 |
| Markdown | 原字符串与版本内相对资源映射 | 源码、阅读、分屏、查找替换；安全 Mermaid/SVG、高亮 | 未改动的 BOM、CRLF 和未支持语法保留；映射改变不改正文字符串 |
| 文本、代码 | UTF-8 原字符串 | 文本编辑、查找替换、复制；按文件名显示语言 | 原上传字节为来源原件，当前下载从该版本权威正文生成 |
| 任务说明 | 原 Markdown 契约 | 原有轻量内嵌编辑及任务图片流程 | 与文档共用基础编辑扩展和文件输入过滤；保留任务独立保存、原文片段和同步适配 |
| 二进制 | 不可变原件 | 按类型阅读或下载 | 提取文字、格式预览失败不改变原件 |

公共编辑核心为 `editor-core.ts`：StarterKit、列表与链接只注册一份，提供输入规则保护和文件插入分类；任务适配不携带新文档保存 API，新文档不携带 taskId 或任务图片地址。

## 身份、版本与保存

继续复用 Material/MaterialVersion 的稳定身份。新字段明确格式、权威正文、来源原件、补充说明和独立整理版本。ResourceReference 记录确切目标版本；LegacyAlias 保留旧任务图片身份，历史正文不批量改写。

- 正文 create/save/restore 均使用稳定 requestId；save/restore 另带 expectedRevision；同一请求只能重试相同载荷，返回该请求的确切回执。正文与引用同事务提交。
- 标题、文件夹、标签及任务关系走独立 organizationRevision；不生成无意义正文版本。
- 本机草稿包含基准、当前输入、冲突双方、精确待核查请求、上传占位和原始附件字节。工作区、账号、设备和会话分支隔离。
- 编辑器缓冲先交给会话，再写 IndexedDB，最后提交服务端。未完成本机持久化时不能显示“已存本机”；离开前尝试落盘，未完成则阻止无提示离开。强制确认离开或杀进程不等于存储成功。转换失败时额外保存原始Editor JSON，停止发布并提供恢复包；新视图不得用旧有效正文清除这份失败缓冲。
- 上传占位期间暂停整版正文发布。上传结果只替换原会话中仍存在的占位；输入法组词期间不替换正文。复制/剪切含占位的片段会提示先完成上传。
- 两端并发采用版本校验，不做整篇自动合并。比较保留基准、本机和远端；选择保留本机是一次新的有版本校验的保存。存在未完成占位时不能把不完整正文直接另存为无附件的副本。
- 撤销栈属于当前会话，最多40组/16 MiB；刷新恢复正文和待处理状态，不承诺恢复刷新前的全部撤销历史。两视图各自保存光标和滚动；未实现协同光标或操作变换。

## 导入、导出与恢复

应用内“另存为”支持文本↔Markdown、富文档→Markdown/文本。转换仅使用已确认的确切版本，创建新资源并记录来源资源、版本、格式和hash；对话框说明样式、宽度、任务项交互能力、表格等损失，来源按钮返回只读历史。文本与Markdown之间保持原字符串，Markdown表格从富文档转换时采用明确的代码文字降级。未知结果保留相同请求重试，不覆盖源文档。没有提供Markdown→富文档的自动转换。

Markdown 批次导入只关联用户这次选择的文件。相对 URL 在该批目录内解析；`../` 只能定位批次内文件，绝不读取本机未选择路径。映射跟随版本，以资源 ID 和固定版本读取，改名或移动不破坏映射。缺文件可在阅读面选择已有资源补充。

完整文档包保存 manifest、产品正文、依赖的确切字节、来源原件和 SHA-256；Markdown/HTML 是可阅读转换副本。导入重新分配身份并重建引用，依赖资源作为受管文件保存。包预算为128 MiB/100资源，超限明确失败；未知 schema 可原样导出，重新导入要求当前版本能理解它。

“导出本机恢复包”独立于已发布文档包，离线保存 draft.json、待核查请求、冲突、附件字节与校验和；打开不执行或重放请求。包预算256 MiB，待上传列表提供逐附件下载本机字节，缺失或超限附件逐项标记，不能把 `complete:false` 宣称为完整。恢复时先核对原工作区、权限、回执和当前版本，再选择如何继续。

## 阅读预算

服务端正文接收上限为8 MiB、50,000结构/文字节点、64层，独立于聊天摘录限制。浏览器交互预算按实测设定（见 performance-verification.md“编辑体验修复”一节）：打开时富文档超过5,000结构块或1.5 MiB、文本和Markdown超过1 MiB，先以只读分页打开。富文档每页100个顶层块，单页仍超预算时转为每页10,000 Unicode字符的文字阅读，完整格式可下载；文本每页最多10,000 UTF-16单元，分页不拆Unicode代理对，原串及BOM/CRLF保持完整。在硬上限以内（富文档10,000结构块且3 MiB，文本4 MiB）分页阅读提供“仍要编辑”；超过硬上限只能分页阅读和下载。已经打开编辑的文档在输入中变大不会转为只读，只提示编辑可能变慢；下次打开时重新判断。分页只改变视图，不改权威正文。代码高亮只处理100,000字符以内内容。

| 阅读器 | 输入与计算预算 | 行为 |
| --- | --- | --- |
| 图片 | 单次32 MiB | 内嵌原图进入视口附近才读取；缩放与下载保留原图 |
| PDF | 32 MiB、画布8百万像素、搜索前500页、目录1000项 | 分页渲染、缩放、目录与文本搜索；边界明确提示，扫描件无文本时说明 |
| DOCX | 压缩10 MiB、实际展开64 MiB、最多10,000 ZIP项 | SAX预检拒绝DTD；正文/表格/图片在无脚本沙箱阅读，不保证分页版式 |
| XLSX | 同Office字节预算；最多100表、20万定义单元格、累计20万合并覆盖单元格、单区1万格 | ExcelJS解析前验证实际XML坐标与面积；100行30列窗口阅读，不执行公式或宏 |
| 其他文件 | 上传上限100 MiB | 保存原件、下载与实际可得的提取文字，不显示虚假的原版预览 |

ZIP中央目录声明不是可信预算：实际解压流先计数，worksheet几何检查先于ExcelJS对象构造，避免小压缩包或巨大合并区突破内存预算。

## 迁移、回滚及验收

增量迁移先在隔离副本执行，保留旧版本内容与证据hash。`DOVUN_DOCUMENT_READ_ONLY=1` 可在兼容读取代码上暂停新旧资源写通道，继续读取/下载/导出；不能在新格式库上启动不理解格式的旧客户端继续写入，也不以升级前快照覆盖新增数据。

真实本机库只通过SQLite只读备份参与演练。数量、原件哈希、二次执行和基线测试证据见 [backend-verification.md](./backend-verification.md)。老板已明确将真实手机与真实桌面客户端续写、软键盘及Tauri WebView验收保留待办。浏览器模拟和源码检查分别记录，不替代这些验收。
