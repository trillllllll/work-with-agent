# Dovun 文档工作区重构实现计划

- 日期：2026 年 10 月 30 日
- 状态：源码实现与自动验证完成，真实设备验收按老板要求保留待办（详情见 [implementation-status.md](./implementation-status.md)）
- 源码基线：`main@d3def90a43081beb68de03917861a60396510012`

## 1. 目标与已确认范围

把 Dovun 的文档、文件管理和编辑重构为一个连续工作区。用户可以在同一处写正文、粘贴图片、编排代码与表格、引用附件、对照资料，并在电脑和手机继续处理同一份内容。

已经确认的需求：

- 日常内容是文字、图片、代码和附件混合使用。
- 文件存进 Dovun，由电脑和手机访问同一工作区；不做本地文件夹挂载或磁盘双向同步。
- 完整重构管理和编辑逻辑，允许替换现有创建、编辑、预览和附件入口。
- 现有内容、历史版本和引用需要保留；“旧功能没有用起来”不代表可以清空数据。

本计划的技术选型和交互默认值是推荐实现方案，不冒充用户已经确认的逐项偏好。原始计划编写时的交付仅为计划文件；执行代码改造、安装桌面应用、发布服务器分别记录状态，不因计划落盘而视为已授权发布。

任务、规划和记忆继续承担各自职责。任务说明保持轻量内嵌编辑，使用公共编辑能力；独立长文可以关联多个任务，不把每条任务自动转换成资料库里的独立文档。

### 整体验收场景

电脑新建“支付方案” → 输入标题、列表、表格和代码块 → 粘贴截图、插入 PDF 和 ZIP → 切换阅读、打开参考 PDF 对照 → 返回原编辑位置 → 文档改名、移入文件夹并关联两个任务 → 从任一任务打开同一文档 → 手机读取并继续修改 → 电脑收到新版本。

同时覆盖上传中切换文档、刷新恢复草稿、断网后重新连接和两端并发修改。只有这条链路及其失败恢复走通，才算完成重构。

## 3. 推荐产品与格式选择

### 3.1 每种内容只维护一个权威正文

为混合图文提供可视化写作，同时保留文本文件的原有性质。不同格式共用工作区、资源管理与保存协议，不强制使用同一种编辑方式。

| 内容 | 权威保存形式 | 编辑与阅读方式 |
| --- | --- | --- |
| 新建 Dovun 文档 | 版本化 `richdoc-v1` 产品 JSON schema | 默认可视化编辑，可切阅读；不提供可写 Markdown 源码模式 |
| Markdown 资料或导入 `.md` | Markdown 字符串，保留未改动原文 | 源码、阅读、分屏；解析不支持的语法保留原文 |
| 普通文本、代码 | 原文本及明确编码、语言信息 | 文本编辑、查找替换、代码高亮与复制；不执行代码 |
| 任务说明 | 保留现有 Markdown 存储契约 | 内嵌可视化编辑，能力按 Markdown 适配器限制 |
| 图片、PDF、Office、其他附件 | 不可变原始字节 | 按类型阅读或下载；提取文字和预览是派生内容 |

`richdoc-v1` 是推荐技术选择，原因是图片展示属性、附件卡片和稳定块标识需要明确保存，不能依靠富文本与 Markdown 反复转换。产品 schema 与 Tiptap 内部 JSON 显式转换，不能直接把某个编辑器版本的内部格式当作长期协议。

首版富文档节点包括段落、标题、列表、任务列表、引用、代码块、表格、分隔线、图片、文件引用和普通链接。图片支持替代文字、说明和受限宽度；代码块保存语言；附件保存资源 ID 与确切版本。未知节点或较新 schema 保留原始内容并只读，禁止解析后丢弃再保存。

旧 `text` 不自动解释为 Markdown，旧材料不自动转换成富文档。格式转换通过“另存为”创建新资源，保留来源版本，展示具体不能保留的属性。Markdown 导出和富文档导出是显式转换，不声称双向无损。

导入 Markdown、文本或代码后，首次上传字节作为来源原件保留。编辑产生新版本时，该版本的读取、下载和导出均从该版权威正文按声明的编码生成；“下载来源原件”是另一个明确操作，不能让新版本的原件接口继续返回首次导入的旧文件。

### 3.2 新建与插入的默认行为

- 主按钮“新建文档”默认创建富文档；菜单另提供“Markdown 文件”和“文本文件”。直接进入可编辑工作面，使用“未命名文档”作为默认标题，不要求先填表才能写。
- 导入保留原格式，标题区显示可辨认的类型；模式按钮由格式能力决定，富文档不显示源码入口。
- 本地草稿可以先产生临时身份；创建提交使用稳定请求标识，云端资源 ID 返回后一次性关联，重试不产生第二份文档。
- 粘贴、拖入、插入菜单进入同一个上传流程：图片默认内嵌，其他文件默认显示附件卡。
- 内嵌图片作为受管资源保存，默认收在文档的“使用的文件”中，不把每张截图强制堆进根目录；可单独找到、复用或整理。
- 文件与文档能多处复用。删除一处引用或解除任务关联不删除原件；移入回收站前展示引用影响。
- 文档内嵌资源默认固定版本，替换图片或附件是明确操作。任务导航和普通文档链接默认跟随最新版本。

## 4. 统一资源模型与不变量

以下为目标领域模型，新增名称不要求机械替换所有现有表名。实施时通过增量迁移和适配层收敛到一个写入权威。

| 对象 | 职责和关键字段 |
| --- | --- |
| Resource | 稳定 ID、类型、标题、当前内容版本、组织版本、权限范围、文件夹、标签、归档/回收状态 |
| ResourceVersion | 资源 ID、不可变版本号、`format/schemaVersion`、正文或原件引用、内容摘要、作者和时间 |
| Blob | 不可变字节、SHA-256、大小、MIME、存储键；不直接向前端暴露存储路径 |
| ResourceReference | 引用方及其版本/节点、目标资源、跟随或固定模式、目标版本；覆盖文档内嵌、任务关联和固定证据 |
| ResourceDraft | 按工作区、用户、资源、设备与编辑会话隔离的基准版本、草稿、待上传文件和请求状态 |
| Folder / Tag | 组织、导航和筛选；不承担资源身份，不隐式决定权限 |
| ResourceDerivative | 按资源版本产生的索引、提取文字、缩略图、格式预览及失败状态；可重建，不替代原件 |
| LegacyAlias | 旧材料 ID、旧任务图片身份与新资源的可审计映射；历史链接继续解析 |

必须保持：

1. 移动、改名、关联任务不改变资源 ID，也不产生无意义的正文版本；内容版本与组织版本分开。
2. 现有 material ID 尽量作为资源 ID 保留。需要转换的 ID 使用永久映射，不批量改写历史正文。
3. 文件内容哈希只用于完整性校验和存储复用；相同字节不自动合并用户可见的两份资料，也不泄露其他权限范围中是否存在该文件。
4. 历史文档、已发送 AI 上下文、记忆证据、结果报告固定到当时的资源版本及摘要，不跟随最新版。
5. 独立资源正文保存与引用集合更新在云端同一事务完成。数据库提交前原件必须已经完整落盘；事务失败留下的暂存字节不得被当成已发布资源。任务本机副本与云端引用不适用跨库事务承诺，按第 5.4 节协调。
6. 富文档块 ID 在编辑中稳定，复制粘贴生成新 ID。块 ID 用于引用和定位，不据此宣称支持自动并发合并。
7. 原件上传成功、文档引用保存成功、派生预览成功是三个独立状态；某种预览失败不能破坏原件或把文档误标为上传成功。
8. 当前版本、历史版本、草稿、未完成上传和兼容别名都参与存储回收判断；不能只统计正文当前引用。

云端无法枚举未联网设备的草稿，因此“无服务端引用”不是删除已提交资源的条件。已提交资源及已完成但尚未关联的上传结果保留至明确处置；自动过期清理只处理未提交暂存数据，并保留可核查的上传状态。本地附件在最终引用提交确认前保留可恢复副本。回收站资源的永久删除还需满足明确保留策略和历史引用检查。

### 权限与工作区

沿用现有清单/收集箱授权边界。全局文件树只改变人的导航方式，不能扩大 MCP 或外部连接的可读范围。整理文件夹、添加标签、关联其他任务，不自动授予文件权限。

新资源默认沿用创建上下文的权限范围；无清单上下文时使用现有全局/收集箱范围，不能因 `folderId` 推断授权。插入已有资源前检查访问权限；原件、缩略图、提取文字和搜索结果执行同一授权规则。图文中引用了无权访问的文件时显示受限状态，不返回内容或敏感标题。

绑定服务器时，同一云端工作区为内容版本权威，设备持有草稿和缓存。未绑定的独立本机模式继续使用相同接口契约，但不承诺具备跨设备访问。绑定、退出登录、工作区切换不能把旧草稿或缓存交给另一个工作区。

## 5. 编辑会话与保存协议

### 5.1 文档会话独立于标签页

`DocumentSession` 拥有正文、基准版本、撤销历史、草稿与上传状态；标签页和分屏只拥有光标、滚动、阅读模式等视图状态。同一浏览器窗口重复打开同一可编辑资源复用会话；历史版本以独立只读视图打开。跨窗口使用草稿分支和版本校验，不能假定共享同一内存实例。

从 `DescriptionEditor` 抽取通用编辑内核、格式工具和资源插入能力。任务保存适配器继续处理任务标题/说明；独立文档适配器处理资源正文。不得把任务 API、任务图片 URL 或 `taskId` 注册表复制到新文档组件里。

推荐模块职责：

- 编辑内核：内容输入、选区、撤销、格式工具、中文输入法状态。
- 格式适配器：产品 schema 与编辑器状态的转换、格式能力、可读渲染和导出。
- 文档会话：草稿持久化、版本提交、上传插入、冲突和恢复。
- 资源服务：身份、内容版本、原件、引用、组织和权限。
- 工作区视图：打开/关闭/切换文档及布局，调用会话，不直接提交正文。

### 5.2 保存顺序和状态

输入 → 本地草稿落盘 → 合并待提交变化 → 带基准版本提交 → 服务端事务回执 → 更新已确认版本。

可沿用现有任务机制的 250ms 草稿节流、2s 停顿提交、10s 连续输入检查点作为初始参数，实施时核对常量并按文档负载验证。中文组词不被格式化、保存回写或远端刷新打断。离开文档先确保本地草稿持久化，不等待网络才能切换。

界面明确区分“保存中”“已存本机，等待同步”“已保存到 Dovun”“保存失败”“存在冲突”。收到旧请求成功时只更新对应已确认版本，不能覆盖用户随后输入。内容未变化不重复产生版本，不为每次按键建历史记录。

每次写入带资源身份、`expectedRevision`、格式/schema 版本、`requestId` 和正文摘要。相同请求标识只能重试完全相同的载荷；内容变化使用新请求。超时先保留待核查状态并查回执，不能因没收到成功就换 ID 再执行。

### 5.3 两端修改与离线

- 首版使用乐观版本校验，默认不做整篇富文档自动合并，也不采用最后写入覆盖。
- 远端更新且本地没有编辑时载入新版本；本地已有草稿时保留草稿并提示比较。
- 冲突提供双方内容、基准版本和可读差异，可人工合并或另存副本；决定前不得丢弃任一稿。
- 已缓存正文支持离线编辑；新文档和未上传文件先保存在当前设备。未缓存原件不能假装离线可读。
- 浏览器存储配额不足或附件未能持久化时显式提示，不能显示“已存本机”。
- 重连后先确认身份和权限，再核对版本、恢复上传和提交；不自动重放已拒绝的写入。

### 5.4 任务说明引用资源

任务文字仍使用现有本机副本与同步机制，资源原件归云端工作区。任务说明内插图或文件引用时，优先延续现有任务版本映射和云端引用命令通道，在同一操作记录中保存原任务、基准版本、目标资源版本及稳定请求标识。

本机正文落盘与云端引用确认分别记录；全部完成前显示待同步，不能把某一端成功当成整个引用操作成功。引用投影需要重放时使用幂等操作与可恢复 outbox，版本或权限冲突保留原任务草稿及已上传资源，不凭猜测覆盖服务端。任务关联、内联引用和手工附加资料的关系需在兼容测试中分别核对。

## 6. 文件上传与引用

保留现有分离式上传能力，普通文件不回到旧的 Base64 大载荷路径。当前库上传通道上限为 100 MiB，旧知识接口的 8 MiB 限制不应成为新界面的隐含上限；调整上限必须统一前端、服务端和转发规则。

上传记录捕获：工作区、原文档会话、插入节点/书签、文件名、MIME、大小、稳定请求标识和本地文件持久化状态。

处理顺序：

1. 文档创建稳定占位，并持久化文件或说明尚未持久化。
2. 申请上传、传字节、校验大小与哈希；上传状态有租约和幂等回执。
3. 提交资源版本，取得资源 ID、确切版本和读取能力。
4. 替换原文档中的占位，按正常正文保存流程提交引用。
5. 用户切换文档后仍更新原会话；原占位被删除时不再强插，只保留可恢复上传结果。

上传失败保留占位和草稿，允许重试、移除或查看原因。重复回执不能重复插入。取消文档里的引用只取消该引用；是否删除已上传资源由独立回收规则决定。

上传占位仅属于持久化本机草稿，不是可发布的资源引用。占位未完成时允许继续写作、切换和恢复草稿，但暂缓该文档的整版云端提交，显示“正文已存本机，等待附件上传”；其他文档照常保存。用户可以移除占位后提交剩余正文。所有附件取得真实版本并与正文引用一同提交成功后，才显示整份文档“已保存到 Dovun”。

文档内只保存稳定资源引用，不能保存临时 Blob URL、带认证的下载地址或本机绝对路径。导出为外部可使用的 Markdown/HTML 包时收集所需资源并改成相对路径；不能把登录 Dovun 才可访问的链接当作完整导出。

批量导入 Markdown 及配图时，按本次导入的相对路径建立文件到资源版本的映射，保留原件，并把映射存进对应文档版本；显示名和目录移动不能破坏它。仅导入 `.md` 而缺少配图时显示缺失引用并允许补充文件，不擅自读取本机其他路径。目录批量导入只是一次上传，不建立磁盘同步。

富文档保真导出使用带 manifest 的包，包含产品 schema 正文、引用的确切资源版本字节及校验和；HTML/Markdown 是另行生成的可阅读副本。重新导入时分配新资源身份并重建内部引用，不能凭导出包中的旧 ID 覆盖工作区现有资源。

## 7. 工作区和阅读体验

### 桌面

- 左侧：文件夹、最近打开、搜索与筛选；列表支持已有批量整理能力。
- 中间：未打开文档时为文件列表，打开后为完整文档工作面；上方是已打开标签。
- 右侧：按需展开文档目录、文件信息、关联任务、历史版本或 AI，不重复创建编辑器。
- 首版支持两个文档并排对照及比例调整；任意网格、多窗口脱离不在本次完成标准内。
- 关闭标签后草稿会话按持久化状态收尾；重新打开恢复位置。单击预览和明确打开的行为保持一致且可预测，不抢走正在输入的文档。

### 手机

文件列表进入全屏文档，返回恢复列表位置。“已打开”入口切换文档，目录和属性通过面板访问，不复制桌面的多列布局。插入操作提供按钮入口，不依赖拖拽或鼠标悬停。键盘弹出后当前段落、选区和常用操作保持可见。

### 文件能力矩阵

| 类型 | 本次必须完成 | 能力边界 |
| --- | --- | --- |
| 富文档 | 混合编辑、目录、阅读、版本比较、格式保真保存 | 未支持节点只读保留；不执行任意内嵌脚本 |
| Markdown | 源码/阅读/分屏、表格、代码高亮、Mermaid 与既有安全 SVG 渲染 | 与资料、任务、AI 引用共用格式判断；未知语法保留 |
| 文本/代码 | 查找替换、语言显示、复制、文本保存 | 大文件按预算进入只读或分页；不运行代码 |
| 图片 | 缩放、适应窗口、原图下载、替代文字 | 原图保留；预览缩略图不替换原件 |
| PDF | 页码、缩放、目录、文本搜索、恢复阅读位置 | 扫描 PDF 无文本时明确说明；不承诺编辑 PDF |
| DOCX | 复用现有解析能力做正文、表格和图片阅读，并统一入口 | 结构化阅读，不承诺分页版式完全一致；不编辑原 DOCX |
| XLSX | 工作表切换、单元格表格阅读与范围定位 | 需按现有 ExcelJS 能力验证格式、合并单元格等；不运行公式、宏或写回 |
| PPTX及未支持格式 | 保存原件、显示真实能力、下载、可用的提取文字 | 幻灯片画布预览另列后续增强，不将提取文字标为原版预览 |

PDF 阅读器需在 Web 与 Tauri WebView 中验证。现有服务端 PDF.js 依赖只能作为选型线索，不能据此宣称已具备前端阅读能力。代码编辑与高亮库在 P0 做小样本验证并锁定版本，不在计划阶段任意引入整套 IDE。

### 公共组件复用

已核对的公共组件包括 `Surface`、`Button`、`ActionMenu`、`Dialog`、`Popover`、`Select`、`Disclosure`、`Input`。继续使用当前样式变量、浅深色、键盘焦点和弹层行为。

新建领域组件集中在文档工作区内：文件树、打开标签、文档目录、文档会话宿主、附件插入/引用卡、格式阅读器和保存状态。不能让资料库、任务资料、AI 来源浮窗分别复制一套编辑或文件读取逻辑。

## 8. 服务接口与旧能力收敛

### 新服务职责

建议在 `server/src/application/resources/` 聚合资源领域能力，在 `client/src/components/documents/` 与 `client/src/lib/documents/` 分离工作区视图和会话逻辑。这些目录在原始计划编写时尚未创建；现已实现，状态见实施记录。

| 操作 | 关键契约 |
| --- | --- |
| 创建资源 | 显式格式与类型，稳定请求标识；返回资源 ID 与初始版本 |
| 读取资源/版本 | 同一授权入口；返回权威正文、schema、版本摘要和能力，历史版本只读 |
| 保存正文 | `expectedRevision`、格式/schema、正文、请求标识；引用校验与版本提交原子完成 |
| 组织与关联 | 单独组织版本；改名、移动、标签、任务关联不冒充正文保存 |
| 上传与原件读取 | 保留上传回执，流式字节和边界校验；读取同时验证资源与版本权限 |
| 历史比较/恢复 | 对比确切版本；恢复创建新版本，不删除或覆盖历史 |
| 回收与恢复 | 引用影响可查询；逻辑删除与物理回收分开 |
| 查提交回执 | 按身份和请求标识核查未知结果，不能回放其他用户回执 |

新 API 优先放在现有 `/api/v1/library/` 路由族内，保持统一云端转发、缓存和权限通道。即使复用前缀，也必须逐项更新 DTO、二进制转发白名单、离线读取、事件失效和权限测试。

原 `material.*` 命令、资料读取 API 和 MCP 工具通过兼容适配层进入同一资源服务。不能让新旧服务各自写一份正文。新富文档的旧文本读取结果必须标为只读投影，并携带实际格式与版本；旧 `material.update(content: string)` 不得覆盖富文档，返回明确的“不支持此格式写入”及新能力入口。

人工保存与 AI 修改共用底层校验。AI 写入继续经过现有提议/确认与权限规则；计划不扩大外部连接权限。富文档工具返回可理解的块与来源，并使用带版本的结构化修改，不让模型拿提取文字覆盖原文件。

搜索和提取按新资源版本重建，保留现有分页、引用定位和授权。旧记忆证据的 `id/revision/hash` 继续解释为原材料版本，不能因为投影格式变化而重算并替换历史摘要。

资源事件携带受影响资源和版本，前端只更新对应列表元信息与会话。自回显、后台索引完成或其他资料更新，不触发全应用正文重载。

### 旧前端入口处理

| 入口 | 最终职责 |
| --- | --- |
| LibraryPage | 查找、组织、新建和打开文档；移除独立正文创建表单 |
| LibraryPreview | 被公共阅读器和文档工作面替代；保留必要的轻量只读预览适配 |
| TaskMaterials | 选择/关联资料；点击进入统一文档目标，不再维护另一套完整浮层 |
| KnowledgePage / MaterialBrowser / ResourceEditor | 保留清单上下文和筛选，文档编辑统一跳转；记忆编辑仍属记忆领域 |
| 搜索结果 / AI 来源 / 历史版本 | 统一传递资源 ID、版本模式和定位信息；证据默认打开确切版本 |
| 任务说明 | 使用公共编辑内核及任务适配器，保持任务正文契约 |

统一打开目标至少包括资源 ID、最新或确切版本、定位信息和返回来源。新标签默认展示最新可编辑版本；历史、证据与权限不支持的格式始终明确只读。

## 9. 实施阶段与阶段门槛

每阶段在隔离开发数据和测试环境中完成。实施前核对实际分支和未提交修改；需要新分支时使用 `codex/` 前缀。表中的阶段产出是后续交付要求，不是本次已经完成的事项。

### P0 契约和最小技术验证

- 固定资源/版本/引用/草稿契约和富文档 schema；写出 task、Markdown、富文档三种适配器的能力差异。
- 用含列表、表格、代码、图片宽度、附件块和未知节点的合成文档验证 Tiptap 适配；检查旧 Markdown 原文保留。
- 验证 PDF、代码编辑和 DOCX/XLSX 阅读的最小样例，记录依赖、体积、限制和移动端表现。
- 画出桌面与手机的工作面及保存状态，先复用公共组件。
- 为现有数据建立只读盘点和迁移映射规则；新内容预算以固定样本验证后定稿，不能沿用聊天附件的字符上限限制文档。

**门槛：** 同一份测试文档往返保存不丢内容；不同格式的操作能力明确；无未决定的权威正文来源。若推荐 schema 不通过，先修契约，不扩展 UI。

### P1 资源与文件基础

- 增量增加模型、统一资源服务和权限判断，保留旧接口适配。
- 打通上传、原件、版本、固定引用、组织和任务关联。
- 接通云端转发、离线缓存标识、提交回执和局部事件。
- 实现可重复执行的旧材料/任务图片迁移，先在副本中运行。

**门槛：** 同一资源通过新旧只读入口得到一致版本；重试不重复建资源；引用和权限测试通过；不改变运行中的真实数据库。

### P2 文档会话与混合编辑

- 抽取公共编辑内核，分别接任务、富文档、Markdown/文本适配。
- 实现草稿、版本保存、冲突保留、资源插入和恢复。
- 新建文档直接写作；插入图片、代码、表格和附件；阅读与编辑一致。

**门槛：** 本地完整走通创建、混合编排、切换、刷新和继续编辑；任务既有保存回归通过；上传结果不会写入错误文档；大附件上传期间持续写正文并刷新后，正文和占位仍可恢复，云端保存状态不误报。

### P3 统一工作区与入口

- 文件列表、文件树、多标签、目录和双文档对照进入同一工作区。
- 手机全屏文档、已打开切换、插入入口和返回位置完成。
- 资料库、任务、工作上下文、搜索与来源引用统一打开。
- 整理菜单、批量操作、重命名、移动、关联任务接新资源服务。

**门槛：** 同一文档从不同入口打开共用当前会话；移动或改名后引用完整；桌面和手机均能完成主要流程，无旧编辑器副本竞争保存。

### P4 阅读器、搜索和导出

- 完成能力矩阵中规定的 Markdown、代码、图片、PDF、DOCX、XLSX 阅读。
- 同步统一格式解析、提取索引、来源定位与错误提示。
- 实现富文档完整导出包、Markdown 及资源包导出；导出转换产生副本，原文不变。
- 大文件按预算处理，超限提供准确状态和原件下载，不无限加载全部资源。

**门槛：** 在各格式样本中验证阅读、复制、定位和导出；独立导出包离开 Dovun 后仍可使用；未支持格式没有虚假的阅读或编辑入口。

### P5 多端、断网与冲突

- 补齐设备草稿、二进制待上传文件、权限变化和重新连接处理。
- 电脑与手机实际共享同一测试工作区，验证登录后读取和修改。
- 制造上传中断、保存响应丢失、两端并发、切换账号与缓存失效，保留恢复证据。

**门槛：** 完整业务验收链通过；本机草稿与云端成功状态准确；并发不覆盖，跨工作区不串稿；不能只用桌面窄窗口代替手机实际验证。

### P6 迁移演练、切换和旧入口移除

- 在真实数据的受控副本上盘点、迁移、复核，生成数量/字节/哈希/引用清单。
- 完成新旧工具协议兼容、旧证据定位、旧图片链接和回滚演练。
- 逐资源切换唯一写入权威，移除旧前端编辑通道；过渡适配保留明确职责和撤除条件。
- 更新使用文档、功能手册及验证记录，完成代码复核和适当回归。

**门槛：** 不丢数据、不扩权限、旧引用可读、切换后的新增内容可回退读取；无遗留第二写通道。是否安装本机或发布服务器按实际授权单独执行。

依赖顺序：P0 → P1 → P2 → P3；P4 的阅读器可在 P1 契约固定后并行准备；P5 依赖编辑和工作区主流程；P6 在 P1—P5 验收后完成。

## 10. 迁移与回滚方案

### 10.1 盘点与映射

盘点材料、版本、附件原件、任务图片、`wwa-material:` 引用、任务关联、记忆证据、聊天来源、待提交提议及本地草稿。按资源记录旧身份、新身份、旧版本摘要、新版本摘要和实际 Blob 哈希。

旧 `MaterialVersion` 可能同时包含附件原件和补充正文，二者都要保留。迁移时明确主内容类型，将补充正文保留为可访问的原版本说明，不能只迁附件而丢文字。旧混合状态使用兼容视图，不强行伪装成新建富文档。

历史 `contentHash` 的旧算法与新资源摘要分开保存。旧证据继续使用原摘要验证，新格式不能改写历史证据。

### 10.2 切换过程

1. 先部署具备新旧读取与格式识别能力的兼容代码，再允许产生新格式内容。
2. 增量建表/字段、只读回填；迁移键唯一，失败可重试，不重复生成资源。
3. 每个资源在切换时核对旧版本，并在事务内记录映射与唯一写入归属。迁移期间旧写入要么由桥接层进入同一服务，要么因版本变化重新迁移，不能遗漏回填后的增量。
4. 验证历史版本、字节和引用后切换读取，再开放新编辑入口。
5. 旧前端接口和 MCP 经适配层继续工作；不支持新格式写入的旧客户端明确只读或提示升级，不允许覆盖新正文。
6. 在兼容观察和回滚演练完成前，旧表、旧文件和兼容别名均保留；相关物理回收暂停。

生产运行根、本机实际数据路径及云端绑定在执行迁移前重新核对，不能根据历史说明推断。迁移程序只接受明确目标，不默认写入生产或安装应用的数据目录。

### 10.3 回滚

回滚优先切换到兼容读取界面并停用新写入口，保存所有新增正文、版本、原件和引用。必要时富文档只读，继续允许完整导出。

设备端回滚前持久化富文档草稿、临时身份映射、待上传文件和结果未知的请求。兼容客户端必须能只读恢复或完整导出这些状态；不能清空或降级覆盖 IndexedDB，也不能让旧客户端自动重放不认识的新格式 outbox。未联网设备的本地草稿保持原样，待兼容客户端恢复处理。

不能直接恢复升级前数据库快照覆盖切换后写入，也不能在新格式数据上启动不认识该格式的旧应用继续编辑。若必须回退二进制，先验证兼容适配或导出/回放方案；无法保证时保留新兼容版本并暂停写入。

本机与服务器的代码切换、数据迁移和验收分别记录，不能用一端成功代替另一端。导出包、映射表和迁移回执不包含密钥、令牌或访问凭据。

| 回滚 | 新文档、附件、设备草稿和未知结果请求不因回退丢失，可完整读取或导出且不被旧客户端重放 |
