# Dovun 公共控件补齐

2026-10-24。基于 `codex/dovun-workspace`，补齐控件统一中遗漏的页面组件。沿用已批准的默认浅深色参数与 14px 正文字号，不改任务密度、业务接口、数据或用户偏好。

首轮完成源码与隔离验收。后续授权增加：修复自动保存后的版本冲突，验证后提交、push、打包并只覆盖本机 Dovun；服务器不部署。实际安装进度见文末发布记录。

## 查到的问题

旧版有公共变量和基础组件，但设置的底栏开关另有本地实现，资料库及工作上下文用各自的 CSS 重写按钮与输入材质，助手引用与工具记录只套了边框。先前的路由巡检证明页面可渲染、不溢出，并不能证明控件已复用。

## 组件边界

| 同类元素 | 公共组件 | 页面可以保留的内容 |
| --- | --- | --- |
| 主/次/弱/危险操作 | `ui/Button` 原有变体 | 文案、事件、尺寸档位 |
| 内容行、导航/标签页、引用标记、可点卡片、字段触发器 | `Button` 的 row/tab/chip/card/input/plain 变体 | 排布、拖动、业务颜色、时间/标题展示 |
| 输入、正文输入 | `ui/Input`、`ui/Textarea` | 受控值、IME、自动保存、编辑器挂载；复合输入内部使用 inline 变体，外围负责焦点材质 |
| 开关 | `ui/Switch` | checked/disabled/onCheckedChange；底栏保留 44px 命中区域 |
| 勾选与单选 | `ui/Checkbox`、`ui/Radio` | 原生 label、onChange、表单及 ref；任务用圆形，其余用方形勾选 |
| 选择框 | `ui/Select`、`ui/NativeSelect` | Radix 复杂选择与原生 option/form API 分别保留，共用输入与浮层材质 |
| 领域标签与普通状态标记 | `ui/TagChip`、`ui/Badge` | 标签颜色、名称、首字缩写与测量；可点击标签通过 asChild 组合公共 Button |
| 卡片、输入容器、浮层表面 | `ui/Surface` | as、间距、尺寸、滚动、领域状态；五种材质不在页面复制 |
| 折叠 | `ui/Disclosure` / 原有 `ui/Collapsible` | 原生 details 与受控 Radix 语义分别保留，不替换业务状态逻辑 |
| 菜单、弹窗、轻浮层 | `ui/DropdownMenu`、`ui/ActionMenu`、`ui/Dialog`、`ui/Modal`、`ui/Popover` | 组合内容与业务回调；Portal、键盘、关闭与焦点由公共组件提供 |
| 数据表选中行 | `ui/TableRow` | 单元格、排序与选择数据；选中/悬停/焦点由公共行规则提供 |

`bare` 只去除按钮的默认几何尺寸，不去除公共交互规则。`plain` 用于文字命中区、日历格、拖动手柄、颜色/星级等具有专用内容表达的控件；不能用它重造普通按钮。图表数据颜色、任务/标签/优先级语义、富文本生成的内容以及用户 HTML/SVG 不作机械替换。

## 行为和层级

- 菜单内容在公共 `ActionMenu` 边界阻断 click/pointer/mouse/touch 冒泡，菜单操作不打开资料行或启动拖动。
- 手机文件夹内容只挂载一份，避免隐藏侧栏里的菜单也 Portal 到 body。菜单关闭时立即卸载退出层，避免快速重开被旧 outside 监听关闭；保留进入动画，并验证鼠标与键盘重开。
- 资料库 `Modal workspace` 保留右侧助手空间与交互；点击助手不关闭资料编辑。其他弹窗仍按原来的模态/非模态用途使用公共接口。
- 弹窗、工作区弹窗、菜单/选择器/Popover、提示分别使用公共层级变量。嵌套菜单必须实际可见、可点击，不能只统计 DOM 个数。
- 原有 Button 尺寸 API 保留，XS 的 12px 文字、图标和间距不被新变体覆盖。选中格式、筛选、资料行与键盘焦点都有回归断言。

## 防回退

`npm run controls:check` 校验批准参数与公共控件边界。客户端 test/build 均执行 `scripts/check-control-reuse.mjs`：

- `client/src` 的业务/开发页面不能直接创建 button/input/textarea/select/details/summary；原生实现只能在 `components/ui`。
- 控件名称必须导入公共 ui，不允许页面重新定义同名组件。
- 禁止用 role=switch/checkbox/dialog/menu/menuitem/combobox 自建同类行为。

浏览器路由巡检额外检查可见控件的 data-slot，以及主/次按钮的实际背景图，捕获“组件用了，但旧 CSS 又覆盖了材质”。富文本内容生成的勾选不属于产品控件。

- 服务器保持原状；本机应用以文末实际发布记录为准。


## 自动保存版本衔接修复

文字保存过去由编辑协调器直接发请求，成功后只更新草稿分支；列表的 React Query 缓存依赖合并后的事件刷新，因此短时间内仍带旧 revision。修复把成功的文字 PATCH 回包同步到公共详情/列表缓存；任务队列还可沿本窗口、当前认证范围内已确认成功且连续的文字保存版本衔接元信息操作。只在发送前校正此类本地文字版本，不读最新远端版本来强行覆盖，也不自动重试真实冲突。

- 缓存只更新已有列表中的任务，不把任务插进不匹配的筛选；较新回包不被旧回包覆盖。
- 本窗口保存仍在网络中时，可先关闭详情并点完成；元信息写入等待相同任务队列，收到文字保存结果后带正确 revision 发送。
- 不跨远端版本缺口、不跨任务或认证范围，不把元信息写入记成文字保存凭据；失去认证后不再使用旧凭据。
- 不改变输入法、草稿分支、outbox、幂等 requestId、确认及服务器版本检查。
- 新专项阻断列表事件刷新并控制保存回包，验证保存后立即完成、回包未到时排队完成、真实远端修改仍返回 409。旧单行任务回归不再等列表事件来规避问题。

后续修复后的最终联合回归：Chromium、手机 Chromium、WebKit 共 **39 / 39 通过**，其中版本衔接专项 9 / 9；原单行任务交互已去掉等待列表刷新的规避条件。
