# DAYLINE · 第三步：质感版组件设计规范（r3）

> r1 原稿见 `~/Downloads/dayline-porcelain-design.md`。本文件为 r3 修订版，第 1–6 节沿用 r1 原文（青灰描述以第 8 节的蓝灰决定为准），第 7 节记录 r2 修订，第 8 节记录 r3：蓝灰主色与暗色主题。

## 目标

在保留时间安排的清晰度与真实时间比例的前提下，给界面增加可感知的表面、边缘和层次。不是所有控件都凸起；主要实体是任务卡，少量关键操作呼应它。此文件记录这一版的设计选择，不代表唯一正确的"质感"。

风格：暖白陶瓷 / 青灰墨色 / 左上柔光 / 浅层实体。

不采用真实材质贴图、噪点叠加、玻璃模糊作为主视觉。常规界面仅使用 CSS 渐变、高光和柔和投影；模糊仅用于弹窗背后的遮罩。

## 1. 统一材质与色彩

| 角色 | 设计变量 | 值 |
| --- | --- | --- |
| 暖白表面 | --surface | #FFFDF8 |
| 下沉底面 | --surface-low | #F2EFE8 |
| 主要文字 | --text | #293535 |
| 次要文字 | --muted | #626D67 |
| 青灰强调 | --accent | #355B66 |
| 选中浅底 | --accent-soft | #E9F0EF |
| 工作背景 | --work | #E9EEEB |
| 通勤背景 | --commute | #F2EADE |

任务表面使用同一渐变：`linear-gradient(155deg, #fffefa 0%, #faf7f0 100%)`。

色差负责区分表面，不靠多种高饱和颜色区分组件。状态还由文字、勾选或边界表达，不能只依赖颜色。

## 2. 表面与光影层级

| 角色 | 光影规则 | 目的 |
| --- | --- | --- |
| 时间轴底板 | 极轻内阴影，没有外投影 | 提供稳定承载面 |
| 通勤 / 工作区域 | 平面染色，没有外投影 | 表达时间背景，而非另一张卡片 |
| 普通任务 | 顶部 1px 内高光 + 近处接触影 + 远处软影 | 形成轻微厚度 |
| 选中任务 | 同方向高光、青灰表面、清晰边界、稍强投影 | 标记当前操作对象 |
| 已完成任务 | 保留可读文字与表面，只留极弱内高光 | 降低优先级但不抹去记录 |
| 弹出层 | 较大范围的柔和外投影 | 明确覆盖关系 |

禁止在时间轴、时间背景、任务外壳、任务内部同时添加外投影。

```css
:root {
  --material-face: linear-gradient(155deg, #fffefa 0%, #faf7f0 100%);
  --shadow-rest:
    inset 0 1px 0 rgb(255 255 255 / 95%),
    0 1px 2px rgb(63 55 38 / 7%),
    0 5px 12px rgb(63 55 38 / 5%);
  --shadow-pressed:
    inset 0 2px 4px rgb(63 55 38 / 9%),
    inset 0 -1px 0 rgb(255 255 255 / 65%);
}
```

## 3. 组件规范

### 日期工具栏 DateToolbar

日期仍是定位信息的主角。手机主规格为 24px / 34px，字重 600；窄屏降至 20px。系统无衬线字体，不下载外部字体。

箭头与设置保持平面。「今天」使用同材质的小型按键。「新建」使用青灰色实体按钮，作为主要操作。不是所有控件都增加底板。

### 视图切换 ViewSwitcher

日 / 周 / 月使用一个轻微内凹的轨道，只有当前选中项略微浮起。轨道与选中项的明暗关系表达选择，不再额外叠加下划线。当前状态仍通过 aria-pressed 暴露。

### 时间背景 TimeBand

通勤使用浅暖色，工作使用浅灰绿色。背景不占任务列，也不拥有独立外投影。轻微顶缘高光帮助与时间轴底板分离。网格仍可辨认。

### 任务 TaskItem

| 状态 | 表面 | 光影 | 内容 |
| --- | --- | --- | --- |
| 普通 | 暖白渐变 | 微浮起 | 深色标题、次要时间 |
| 选中 | 青灰渐变 | 边界更清楚、投影稍强 | 文字对比保持 |
| 已完成 | 接近底面的暖灰 | 回落，不加外投影 | 勾选 + 可读文字，不整体透明 |
| 紧凑 | 沿用自身状态材质 | 沿用自身状态光影 | 摘要展示，不延长时间 |
| 按下 | 稍暗表面 | 改用内阴影 | 不移动时间坐标 |

任务圆角 10px；极短任务用 6px。手机标题主规格 14px / 21px，桌面 15px / 23px。更窄列和更短任务采用紧凑文本；完整名称和时间通过详情与任务列表查看。

时间轴默认 96px / 小时。装饰不改变时间定位；卡片内部保留固定视觉间隙。重叠逻辑不变：最多两列，额外任务通过 +N 展开。不能把重叠任务画成先后进行。

### 底部导航 BottomNav

导航整条不单独浮起，当前入口使用轻微染色的局部选中面。非选中项保持平面。组件页为原型验收入口，并不意味着真实产品需要保留这一导航项。

### 弹出层与输入

弹出层圆角 22px，明显但柔和的覆盖投影。输入框使用同色系的下沉表面，不另引入玻璃或塑料风格。保留键盘焦点、Esc 关闭和校验提示。

## 4. 间距、圆角与动态

基础间距为 4 / 8 / 12 / 16 / 24。手机时间轴底板圆角 16px，普通任务与按钮 10px，浮层 22px。曲率按角色分配，不要求所有组件一个数值。

过渡主要限于背景、颜色和阴影，160ms。时间轴上的任务不使用位移或缩放来表现悬停，避免暗示任务时间发生变化。系统要求减少动态时禁用过渡。

## 5. 代码职责

- `tokens.css`：可复用的色彩、材质、圆角和光影变量。
- `styles.css`：原有结构与布局基础。
- `material.css`：把同一种材质分配给不同组件角色；不改业务逻辑。
- `components.js`：工具栏、任务、时间背景、组件展示等共享视图。
- `layout.js`：真实时长、重叠与位置。
- `app.js`：交互、校验、任务状态和本地保存降级。

组件页与日程页调用同一个 TaskItem，不另外绘制一套只供展示的假组件。

## 6. 验收范围

整页先看三件事：任务是否比容器容易阅读；实体层是否有明显主次；高光方向是否一致。

自动检查覆盖：原有布局和交互、七种屏宽的溢出、材质状态差异、减少动态偏好。截图来自实际 HTML 渲染。

仍需后续验证：手机真机、Safari、系统大字体、紧凑工具栏的触摸热区，以及不同浏览器下本地保存的可用性。没有接入真实账号、后端或云同步。

## 7. r2 修订记录（2026-11-04）

r1 评审发现四类破线（热区、小字、对比度、轴上一步完成），本轮全部修复，另收编两处工程隐患。

### 7.1 触摸热区统一 ≥44×44

- 日期箭头、设置、新建、「今天」、「待安排」在桌面与移动端（含 <359px）全部 ≥44×44。r1 移动端箭头 32×44、工具图标 37×40、新建 37×37 全部破线。
- 视图切换改为「44 命中区 + 内层 span 胶囊」结构：按钮承担命中面积，视觉胶囊由 `span` 承担，轨道高度不变大。
- 「+N」溢出轨道从 32px 加宽到 44px（JS 预留 38→50）。

### 7.2 文字下限

- 正文（任务名、列表标题）≥12px：micro 标题 11→12，移动端时间文字 10→11。
- 辅助信息（时间戳、计数、meta）≥11px：删除 <360px 的 9px 时间文字。
- 参照物（时间刻度、竖排带标、画廊标注）≥10px：8px/9px 标注全部清除。原则不变：放不下先改展示方式，不缩字。

### 7.3 对比度修正（全部实算 ≥4.5，多数 ≥5）

| 项 | r1 | r2 | 实测 |
| --- | --- | --- | --- |
| 通勤墨 / 通勤底 | #7D684B（4.45 ✗） | #6B573A | 5.77 |
| 溢出钮文字 / 溢出面 | #64776D（3.77 ✗） | #47584E | 5.98 |
| 时间刻度 / 底板 | #687166（4.53 无余量） | #5D685C | 5.21 |
| 竖排带标 / 带底 | #5E6C63（4.64） | #535F55 | 5.63 / 5.31 |
| 月历外日 / 底板 | #7C8693（约 3.3 ✗） | var(--muted) | 4.81 |

### 7.4 轴上一步完成

TaskItem 由单个按钮重构为「容器 + 两个并列按钮」：

- `.task-open` 覆盖整卡，打开详情；
- `.task-check` 右下角 44×44 命中区（视觉为 18px 状态圆点，复用 status-dot 材质），一步切换完成；
- ≤18 分钟的 micro 卡不放圆点（高度容不下 44 命中区），完成走详情或任务列表；
- 完成态统一由「圆点填充 + 标题次要色 + aria」表达，时间行不再重复「✓ 已完成」文案。

### 7.5 工程收编

- `--hour-height` 单一来源：JS 从 CSS 变量读取（r1 在 layout.js、TimeGrid、app.js 三处硬编码 96）。
- 时段边线与任务左色条入 token：`--edge-rail / --edge-rail-muted / --edge-work / --edge-commute`（r1 为 #8aa39a、#c6cee1 等裸值散落）。

### 7.6 验证记录

- 4 段内联 JS 语法检查通过；58+7 处替换全部精确匹配。
- DOM 断言：每张卡有独立「标记完成/标记未完成」按钮；+N 溢出轨合并相邻段正常。
- 交互实测：轴上点击完成 → toast「已标记完成」、按钮翻转、卡片 done 态，再点还原。
- 移动 390px / 桌面 1280px 截图经视觉模型检查：无截断、无重叠、无溢出；两条疑似问题（带标被卡片遮挡、右面板底部截断）经坐标测量与滚动设计核实均为误报。
- 遗留（已知待定项，非本轮回归）：工作带色在桌面仍偏弱（11:00–12:00 空载区近于不可见），对应待定的「六色时段公式 + 带边界载体」；竖排带标与卡片的 4px 间隙在窄列下偏紧，六色公式定稿时一并处理。

## 8. r3：蓝灰主色与暗色主题（2026-11-04）

用户拍板：主色定为**蓝灰**（弃青灰 #355B66），暗色本轮加上。气质简报：阴天清晨湖面 / 雾里远山——天空、水、山同属一个蓝灰层次渐变，没有明确色块，只有光线在退让；配**暖白 #F4F1EA** 或**炭黑 #1E242B** 最稳，想提气加一点**黄铜**；忌纯白与高饱和亮色。

### 8.1 明色改动

- 强调色 #355B66 → **#43618C**（暖白面上 6.21，选中底上 5.40）；选中浅底 #E7EEF8；选中边 #A9BCDA；任务左色条 #8E9FBC；主按钮渐变改蓝灰系（#4E6C99→#3E5883，暖白字 6.37）。
- 其余暖白陶瓷材质不变。明暗两套共用同一批 token，规则层零硬编码。

### 8.2 暗色规范（`data-theme="dark"`，跟随系统初始 + 手动切换 + localStorage 记忆）

| 角色 | 值 |
| --- | --- |
| 画布 / 底板 / 卡面 | #1E242B / #20272F / #2A333E→#262E38 渐变面 |
| 文字 / 次要 | 暖白 #F4F1EA（13.4+）/ #A3AEBB（5.7+） |
| 雾蓝强调 | #96AFCF（底板 6.7；选中底 4.8+） |
| 工作带 / 通勤带 | 蓝灰洗色 rgb(122 146 168 / .20→.13) / 黄铜洗色 rgb(196 164 118 / .14→.09) |
| 黄铜点睛 | #C9A876——只给「现在」线与通勤标识 |
| 主按钮 | #56749E→#425E86 渐变，暖白字（5.18） |
| 勾选圆点描边 | #96A5B7（卡面 5.09，超图形件 3:1 线一倍余量） |

阴影反转：内高光 rgb(244 241 234 / .05–.09)，投影换近黑蓝 rgb(0 0 0 / .16–.55)；光源方向不变（左上）。`color-scheme: dark` 交给原生控件。

### 8.3 工程含义（对真实迁移最重要）

- material.css / styles.css 中约 60 个裸 hex **全部收编为 ~85 个皮肤 token**（明暗各一份），规则层只引用 `var()`。暗色不是第二套皮肤，是同一套变量的另一半——这正是将来写回 `approved-tokens.json` 的形状。
- 主题切换：demo-bar「深色/浅色」按钮，`document.documentElement.dataset.theme`，初始 `prefers-color-scheme`，localStorage 键 `dayline-porcelain-theme`，meta theme-color 同步 #1E242B/#f7f5ef。

### 8.4 验证记录

- 4 段 JS 语法过；规则层十六进制残留清零（仅 token 定义区含色值）；88+7+7 处替换全部精确匹配。
- 暗色实测：主题持久化、meta 同步、轴上一步完成在暗色下正常、明暗切换按钮文案翻转。
- 视觉验收两轮：第一轮发现 3 处（空心圆点 2.25:1 不达图形件 3:1 线、竖排带标、面板原生滚动条亮条）+ 漏网硬编码 nav-item #646f65，全部修复；第二轮四项全部通过，明色确认无 teal 残留。
- 遗留（并入既有待定项）：工作带洗色在桌面仍偏含蓄（本轮已提亮一次）、竖排带标 10px 偏小、「地铁」暖色相与蓝灰基调的关系——三者都归「六色时段公式 + 带边界载体」一次定稿。
