## 可重放命令

在仓库根目录运行，使用 Node 22。数据库文件必须不存在，文件名须为 `learning-workflow-benchmark-NAME.db`，并处在系统临时目录。输出 JSON 也必须不存在，避免覆盖原始证据。

```bash
/Users/byc/.volta/tools/image/node/22.13.0/bin/node --import tsx scripts/learning-workflow-benchmark.mts \
  --db /tmp/learning-workflow-benchmark-my-run.db \
  --out /tmp/learning-workflow-benchmark-my-run.json \
  --samples 30 \
  --compare /Users/byc/.codex/worktrees/learning-workflow/work-with-agent/docs/design/dovun/learning-workflow/performance-baseline-20261030-v2.json
```

`--compare` 可省略以生成新基线。比较不通过时脚本仍保存 JSON 并以非零状态退出。默认执行后删除自己创建的数据库及其 sidecar；`--keep-db` 可保留合成库供检查。脚本在临时工作目录设置专用 DATABASE_URL 和数据目录后才导入服务，避免 dotenv 读取仓库配置。

每阶段扩展同一份隔离库；测量阶段之间断开 Prisma 后再写入数据。一个固定 20 题会话将作答和事件集中在第一题，以覆盖同题长历史。笔记正文 800 字符，搜索包含标题与正文；历史深页在长历史阶段从第 900 条偏移开始。每个操作先记录一次首次读取，再预热 3 次，采样 30 次，报告中位数、P95、最大值、所有样本、JSON 字节数和页长。首次读取发生在造数之后，不代表冷磁盘。

响应检查包括：搜索/历史每页最多 30 条、会话最多 20 题、每题最多返回 5 次作答及每次最多 5 版判题，首页可继续会话最多 10 条。还检查大量普通动态之后仍能读到已确认 checkpoint。

## 消除重复读取后的 v5

2026-10-30 02:56:37（Asia/Shanghai）完成，沿用 v2 的全部固定预算，**18/18 项通过**，没有修改样本数、数据规模、响应大小预算或页长上限。执行时没有本轮并行测试或构建；结束 load average 为 [3.07373046875, 5.9677734375, 9.13818359375]。不能保证宿主没有其他工作。

本次实际变化集中在 `read.ts` 和 `store.ts`，JSON 的源码哈希与 v4 对比也仅这两项变化：

- 搜索结果按页批取主题，按层批取共用祖先元数据，避免每个结果重复读取相同主题和路径；同主题边界与循环保护保留。
- 首页对人工节点复习安排先构造该用户的节点集合，避免对每个知识点执行相关扫描。
- 历史页一次选择带会话 ID 的作答，再按最多 100 个作答批量读取判分。SQL 窗口每次作答只返回最新 6 版；公开最近 5 版，缺失的当前有效旧版另按 ID 批取，校验其确属当前作答。
- 固定会话按最多 20 题批量读取版本、草稿、来源和援助聚合，每题最多读取 6 次尝试，再统一构造判分 DTO。完整历史仍通过游标可达，没有把历史截断后冒充完整结果。

时间单位为毫秒。3000 节点会话由 v4 的 132.410 降至 20.578 毫秒，首页由 33.582 降至 4.899 毫秒，历史首页由 15.279 降至 1.278 毫秒。响应大小与 v4 完全一致；最大会话 25,745 B，历史首页 68,032 B，搜索 24,545 B。页长仍为会话 20 题、历史与搜索最多 30 条。

修改后 52 条后端专项验证通过，含历史分页可达、当前有效旧判分、跨作答/用户隔离、复习投影、援助记账和迁移。额外明确断言 raw 查询的 version/score/maxScore 为普通 number，完整 DTO 可 JSON 序列化；共享多层祖先、跨主题分页/状态筛选、旧循环路径均有回归覆盖。报告 `/tmp/dovun-practice-backend-results.json`，数值断言的补充报告 `/tmp/dovun-practice-bounded-results.json`。

本轮验证支持“当前实现达到所定合成读取预算”，不证明历史增长完全不影响时间，也不覆盖真实网络、浏览器渲染、模型耗时或生产并发。

## 如何解读

同一数据规模也有波动：3000 节点的会话 P95 三次分别为 86.465、68.193、47.416 毫秒，首页分别为 12.387、17.180、12.505 毫秒。小数据标题搜索出现一次越界、再次确认通过，具体原因尚未定位。响应大小保持一致，说明本场景返回量有界；这些结果不能单独证明运行时间与历史规模无关。长事件会话读取和大地图首页计数可以继续用 SQL profile 定位。

后续比较须保持数据规模、样本数、Node、硬件和计时边界一致。超预算后先核对源码哈希与负载，重复运行确认；不要删去慢样本后宣称通过。网络传输、浏览器渲染、手机真机、多个并发设备以及真实模型质量均不在本基线的验收范围。
